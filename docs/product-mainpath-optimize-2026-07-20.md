## 仍有效产品规则

> 提炼自已归档体验文（ux-nondev-* / shell-chrome）；**全文 UX 只在** [`docs/archive/`](./archive/) · **不**再开第三份 UX 总计划。

1. **唯一业务开跑**：只经 `confirm_start` / `split::confirm`；禁止 UI 旁路 `start_run`。  
2. **拆分是核心屏**：`planned` / `confirmed` 待确认必须落拆分台，不得被聊天默认冲掉。  
3. **拆分台第一屏只两键**：「重新规划」·「执行规划」；可并行 / 写回摘要等进高级或折叠。  
4. **业务可选必人勾**：有 optional 时禁止 auto-start 跳过未勾选。  
5. **主路径跳过执行选项层**：通道 / 并发 / 规划方式默认不挡「拆成步骤」；高级进设置。  
6. **主表面 ≤4**：项目 · 写计划 · 拆分台 · 进度/结果；计划管理 / doctor / 日志调试台降权。  
7. **概念预算**：主路径第一句人话，无 run_id / VERDICT / 引擎名；高级默认折叠。  
8. **壳层减法**：顶栏无全局阶段条；聊天 / 计划管理 / 刷新为 icon + 悬停说明。  
9. **能力保留不删**：replan · multi-provider · 写回摘要 · 监视窗等只藏不砍。  
10. **硬边界**：不换 React/Vue · 不旁路 Mode B · 不重开第二套 Scheduler。

## 1. 目标用户操作流（大改后真源）

```text
【没在跑】
  选项目
    → 主区：写计划（聊天）/ 从模板开始 / 弱入口选已有
    → 核对：全文可读 · 未执行可改 · 点「拆成步骤」

【拆分 · 核心屏 · 禁止草率闪过】
    → 拆分中（进度人话，日志默认收起）
    → 拆分结果台：
         左：波次时间线（谁与谁并行）
         中：步骤卡片（标题 · 一句话 · 可选开关）
         右/下：选中步骤说明 · 依赖 · 编辑/删/并
         顶：并行说明 · 重新拆分 · 「确认并开始」
    → 有业务可选步骤 → 必须停此屏（已有逻辑保留并强化）
    → 高级才「跳过预览自动开跑」

【在跑】
    → 主区只做进度：步骤条 + 状态 + 时长
    → 日志次级/按需
    → 卡住可见 · 可停 · 可换通道（高级）

【收口】
    → 结果页：计划要点 · 做完 · 遗漏 · 回补/结束/回聊天
    → 不是 KPI+终端墙
```

### 1.1 页面角色（大改后只保留这些主角色）

| 角色 | 何时 | 主区内容 | 禁止 |
|------|------|----------|------|
| **写计划** | 无活动 run | 聊天 + 模板 + 计划弱列表 | 第一屏引擎/预算 |
| **拆分台** | plan job planned / 人工确认 | 波次 + 步骤卡 + 编辑 | 工程 critic 芯片默认铺开 |
| **执行台** | running | 进度为主 · 日志为辅 | 多入口抢戏 |
| **结果台** | 终态 / 巡检后 | 摘要收口 | 只有 VERDICT 条 |
| **设置/环境** | 主动点开 | 高级全收此处 | 主路径常驻 |

计划管理、监视窗、医生页：**保留能力，降权为工具**，不占主叙事。

## 2. 计划拆分：必须完善（本计划第一优先）

> 拆分是 PRODUCT 第 ③ 步，也是相对 Codex「人看清再让 agent 干」的关键闸。  
> 现状能力：Mode B plan job · `renderConfirmPanel` 波次列表 · 删/改依赖 · replan · sanitize deps · 可选任务 · critic 备注。  
> **问题不是「没有拆分」，而是拆分屏仍像工程师确认页，且默认 auto-start 让主受众看不见拆分质量。**

### 2.1 拆分产品规则（新）

| # | 规则 | 说明 |
|---|------|------|
| **R-S1** | 拆分结果默认**给人看** | 主受众默认停在拆分台；「规划后自动开始」改为高级（**产品默认翻转**：见任务 S0） |
| **R-S2** | 一屏看懂「谁先谁后、谁和谁一起」 | 波次时间线 + 并行角标；少 `depends_on` id 串 |

### 2.3 拆分中（planning）目标

- 主文案：正在把计划拆成可执行步骤…

- **规划日志默认折叠**（需要再展开）；禁止默认终端墙

#### 2.5.4 借鉴后的拆分质量条（planner / critic 目标话术）

拆分台顶部**一条**人话（可展开），优先这些信号：

1. 可能 **串行过多**（最宽波=1 且步数多）→ 主推「让可并行的真正并行」  
2. 可能 **过碎**（&gt;15 步或大量 1 行标题）→ 建议合并  
3. 可能 **过粗**（&lt;3 步且计划很长）→ 建议再拆  
4. 缺 **完成标志** 的步骤占比高 → 提示补「怎样算做完」  
5. 业务可选未勾选 → 说明「确认后不会跑」  

（对应 S9 + S13；消费已有 `critic_*` / layers / optional，少造新协议。）

## 3. 全流 UI 大改要点（非拆分屏）

### 3.1 全局壳

| 项 | 大改后 |
|----|--------|
| 侧栏 | 仅项目列表 + 底部设置/环境；弱边框 |
| 顶栏 | 项目名 · **五步阶段条** · 当前计划短名 · 少按钮 |
| 主区 | 同时只强调一个角色（写/拆/跑/收） |
| 概念预算 | 第一屏 ≤ 3：项目 · 计划 · 进度/结果 |

### 3.2 写计划

- 欢迎：PRODUCT 一句话 + 添加项目 + 模板  
- 聊天主窗：引导「说清要干什么」；保存后主 CTA **「拆成步骤」**（取代含混的「执行此计划」若造成「已经在跑」错觉）  
- 计划列表：标题 + 未执行/已执行；默认藏已执行  

### 3.3 执行台

- 步骤进度为主（卡/条），状态：排队中 / 进行中 / 已完成 / 已卡住 / 失败  
- 日志按步骤点开或次级面板；默认不砸全屏 term  
- 独立监视窗：进度优先（已有窗可复用，内容换权重）

### 3.4 结果台

- 计划要点 · 做完 · 遗漏 · 一键回补 / 接受结束 / 回聊天  
- 无巡检时诚实：「步骤跑完 ≠ 对照计划验收」

### 3.5 视觉一体（大改视觉，仍不换栈）

- 同一套 tokens 上重做 **layout 层级与组件样式**（可大改 css，**不**引入组件库）  
- 主按钮唯一高对比；卡片 1–2 级阴影；状态色 ok/warn/danger/accent  
- 允许较大面积留白与主区比例调整（侧栏可窄）  
- **禁止**：深色跟风、像素抄 Codex、React 重写
