## 0. 上一轮为什么不合理（先纠偏）

| 上一轮做法 | 问题 |
|------------|------|
| 主叙事 =「`force_serial` 导致无并发」 | 用户真正卡的是：**看不懂这步干什么、怎么算做完、要不要开始**；并发只是次级痛点 |
| 建议「按 P0/P1 波次重算 DAG」当第一交付 | 对「完全不懂代码的人」零意义；对 PM 也是后台质量，不是屏上可读 |
| 用 run 日志 / adapter 名解释体验 | 违反 PRODUCT：主路径不暴露引擎 / schema / worker 口吻 |
| 把「修启发式」当成产品方案 | 修对了依赖图，若卡片仍写「你是执行任务 t1 的 worker」，主受众仍劝退 |

**本计划改锚点：**

```text
第一问：这人打开拆分台，10 秒内能不能回答——
  · 一共几步？谁和谁能一起干？
  · 点开一步：要干什么？怎样算做完？要不要先等别的？
  · 要不要点「确认并开始」？
第二问：同一屏能否同时伺候两种人——
  · 甲：完全不懂代码，只想把事情办完
  · 乙：产品经理，懂一点技术，需要时能看到「改哪一块 / 怎样验收」
```

并发与依赖 **要修**，但排在「人话说明分层」之后或同波，**不得**单独当整份计划的中心。

## 1. 两种读者（设计真源）

### 1.1 甲 · 只想把事办完（默认主路径）

| 要 | 不要 |
|----|------|
| 短标题（计划里那句话，去掉 ☐/技术括号） | `t1` / `worker` / `VERDICT` / 文件路径当第一句 |
| 一句话：这一步会帮我做成什么 | 「你是执行任务…的 worker」 |
| 一句：怎样算做完（结果长什么样） | 落点 / 自测 / facade / soft-fill |
| 一句：要先等谁（用人话步骤名） | `depends_on: ["t2"]` |
| 顶栏：共几步 · 几批一起干 · 点「确认并开始」 | 默认展开高级通道 / role / scope |

**成功标准（甲）**：不打开「完整说明」也能决定开始；完整说明默认折叠。

### 1.2 乙 · 懂一点技术的产品经理（同屏可进阶）

| 要 | 不要 |
|----|------|
| 默认层与甲相同（不强迫先懂） | 两套完全不同的 App / 模式开关「小白模式」 |
| 展开「技术说明」可见：改哪些文件/模块、步骤要点、完成判据原文 | 把执行 AI 的 system 脚手架（CCO_DONE、元流程禁令）当产品正文 |
| 需要时改「谁先谁后」、可选步骤勾选 | 默认露出 provider 枚举当主 CTA |
| 摘要条诚实：若一批一批做、不能并行，用人话说「将按顺序做完」 | 写 `layers=11` / `force_serial` |

**成功标准（乙）**：展开一层即可对照计划验收；仍不需要读 `run.json`。

### 1.3 同屏分层（禁止第三套心智）

```text
【默认 · 甲乙共用】
  标题
  一句话（要做成什么）
  怎样算做完
  等待：… / 可马上开始
  [可选] 本批会和谁一起做

【展开 · 乙优先 · 甲可忽略】
  技术说明（从计划表抽出的落点/步骤；无则隐藏整块）
  完整说明（给执行 AI 的正文，已剥脚手架；默认再折一层）

【高级 · 默认折叠 · 已有】
  执行通道 / 角色 / 范围
```

同一屏新概念仍 ≤3：**步骤 · 等待 · 怎样算做完**。  
「技术说明 / 完整说明 / 高级」都是展开项，不计入首屏概念。

## 2. 现状盘点（对照截图与真实拆分产物 · 2026-07-22）

| 位置 | 现状 | 甲感受 | 乙感受 |
|------|------|--------|--------|
| 左栏卡片一句话 | `summary`/`prompt` 首行 = **「你是执行任务 t1 的 worker」** | 完全看不懂 | 知道是模板垃圾 |
| 右栏「这一步做什么」 | 短读仍常落到 worker 句；展开是工程表（落点/自测/依赖）+ worker 头 | 劝退 | 能抠到有用行，但噪音大 |
| 顶栏摘要 | 「共 11 步 · 约 11 波 · 最宽波 1 路（上限 2）」 | 「波/路」像术语；不知道为何不能一起干 | 能读出串行，但缺「为什么」人话 |
| 依赖 | 每步只等上一步（文档顺序链） | 觉得必须等很久 | 与计划「可并行」表矛盾，不信任拆分 |
| 标题 | 带 `☐`、长技术副标题 | 像未完成勾选表 | 与文档 ✅ 状态不一致 |
| `done_when` / `acceptance` | 计划表有「完成定义」，**未结构化写入** DTO | 右栏几乎无「怎样算做完」 | 只能翻完整 markdown 表 |

**根因分层（给实施，不给用户看）：**

1. **展示层**：`oneLiner` / `summary` 取了 worker 脚手架首行；右栏默认没抽「完成定义」。  
2. **数据层**：启发式把计划 `####` 包塞进 `prompt`，**没有**抽出 `summary` / `done_when` / 人话依赖。  
3. **派工语义**：`####` 主路径 `force_serial` → 全链依赖 → 永远「一批一步」（次级，S2 修）。
