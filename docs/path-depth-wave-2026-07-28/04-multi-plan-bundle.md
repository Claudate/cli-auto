## 目标

支持 **多材料/多计划**（bundle）：

```text
需求材料 ×N
  → AI 梳关系 →《索引》md（人认领）
  → N 份《执行计划》md（每份可独立验收）
  → 进入分计划拆分（见 05）
```

可观察结果：用户能指认索引、≥2 份计划、计划间建议可并/必串；单波建议 ≤5～7 份计划。

## 非目标

- 把多 md 粘成一篇再拆（假多计划）  
- 无确认自动连开多 run  
- Jira/甘特/人天  
- 拍扁成超级 Task DAG  

## 为什么多计划而不是长文档

| 长单文档 | 多执行计划 |
|----------|------------|
| 难核对、难停、难单点重试 | 可独立验收、停、重拆 |
| 巡检「对照谁」糊 | per-plan 巡检清晰 |
| 费用与并行难叙事 | 每计划任务数/波次可讲 |

**切割启发式**（提示词规则）：

- 不同可感知结果 → 不同计划  
- 不同主风险 → 不同计划  
- 强依赖 → 计划间 after；无共享文件所有权 → parallel_ok  
- 同结果步骤 → **任务**（05），不升格计划  

## 索引文档（给人）

一页可扫，建议章节：

1. 本波要推什么（一句话）  
2. 材料清单与关系（谁依赖谁、谁是噪音）  
3. 将生成/已生成的执行计划列表  
4. 建议：哪些可并肩、哪些必须先后  
5. 本波不做  
6. 怎样算本波齐  

认领索引 **≠** 开跑。

## Bundle（系统对象 · 薄）

```text
WorkBundle { id, project, plans[], edges[] }
PlanRef   { plan_path, job_id?, task_count?, status }
PlanEdge  { from, to, kind: after | parallel_ok }
```

- app 用例组合；禁止上帝 Manager  
- UI：上总览卡片，点入仍是熟悉的单计划拆分台  
- 确认：对每份 planned 仍走 **同一 confirm 语义**（可批触发，不可旁路）  

## 与单计划模式分离

| | 单计划 | 本波多计划 |
|--|----------|----------------|
| 入口 | 一卡「拆成步骤」 | 索引认领 / 「认领本波」（≠ 开跑） |
| 拆分台 | 现波次台 | 总览 + 进入单计划台 |
| 失败 | 该 job | **该 plan_path**；其它继续 |
