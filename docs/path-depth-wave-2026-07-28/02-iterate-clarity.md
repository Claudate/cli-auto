# 计划 02 · 边聊完善与反馈再完善

> 本波：[INDEX.md](./INDEX.md) · 落地：[landing.md](./landing.md)  
> 问题：用户需求**不清晰**时，如何边聊、如何根据 AI 反馈再改，而不逼一次写成功？  
> 状态：决策向 · W1 主实施 · **智能目标：更懂非技术用户，而非教用户流程** · W0 已要露出反馈动作  

---

## 目标

**一句话**：让 cco 在需求含糊时仍 **更懂痛点、更准理解、更聪明地陪改**，最后能指认「给谁、做成什么」——用户无感「模式/入口」，只觉得 AI 懂行。

把两种完善做成**一等能力**（不是澄清问卷附属）；P2/P3 仅作内部称呼（见 [06](./06-audience-demand-field-research.md) §0′）：

| 用户感受（对外） | 行为 | 产品 / AI 应表现得更智能 |
|------------------|------|---------------------------|
| 「陪我把事说清楚」 | 多轮补充，想法长出来 | 跟得上、记得住、矛盾主动问一句；**当前理解**可见可改 |
| 「你先出一版我改」 | 稿 → 批 → 再稿 | 三行人话可扫；假设不装事实；**按我说的改 / 这版去拆步** |

可观察结果：≥3 轮后口径可指认；不觉得在答题；**不需要**知道任何 P 代号或作业模式名。

## 非目标

- 审讯式长问卷当唯一路径（图 1 反例）  
- 聊着聊着自动开跑  
- 恢复 guided 全量 G0–G4 / 人生 Pack  
- 用技术「版本号/commit」做主文案  

## 与澄清三入口的关系（正交）

澄清入口 = **想清楚的深度**（想清楚再说 / 从想法到计划 / 直接写计划）。  
完善模式 = **时间上怎么变清楚**（边聊 / 反馈 / 材料堆叠）。

| | 边聊 A | 反馈 B | 材料 C（见 04） |
|--|--------|--------|-----------------|
| 想清楚再说 | 常停 Brief | 可 | 少 |
| 从想法到计划 | 常 | 常 | 可 |
| 直接写计划 | 少问 | 改稿 | 常 |

**规则**：L 默认不进占屏 1/5；M/H 澄清可折可跳；完善模式在所有档都允许。

## 边聊完善 · 规则

1. 对话是工作台；主输入始终可达。  
2. 短「当前理解」条：给谁 / 做成什么 / 不做——可点改。  
3. 未钉盘前多轮只出草稿；「这版作数/保存」才写 plan.md。  
4. 已保存再改：重写草稿或改计划；**不**静默 confirm。  
5. 长会话靠 session-digest 压上下文；用户见人话摘要，不见「压缩」黑话。

## 反馈完善 · 规则

1. 任何草稿首屏三行：**做成什么 · 不做 · 怎样算完**；假设折叠。  
2. 主动作（人话）：  
   - **按我说的改**（继续输入）  
   - **换个方向**  
   - **这版可以，去拆步**（主 CTA）  
3. 禁止四按钮同权（展开/仅保存/拆成步骤/直接执行）。  
4. 「直接执行」仅 L 或极短说明；M/H 进 ⋯ + 风险人话。  
5. 再生成带上用户上轮批注（revision 心智）。

## 红线

```text
聊 / 改 / 认领 / 保存  ≠  开跑
拆成步骤             ≠  开跑
唯确认（confirm）    →  开跑
```

## 现状锚

| 已有 | 缺口 |
|------|------|
| 聊天、澄清、Brief、认领、digest | 空态像考场；草稿反馈动作弱；版本/「这版作数」不清 |
| replan / revision_notes（拆分侧） | 聊天侧「按反馈改」未对称产品化 |

## 验收

- [ ] 三轮边聊后口径可指认（**像更懂了**，不是像填完表）  
- [ ] 反馈路径不强制重走满页 1/5  
- [ ] 界面/文案 **无** P1–P6、无「请选择作业模式」  
- [ ] 无聊天直接 spawn worker  
- [ ] 与 [03](./03-path-empty-cta.md) 主 CTA 不冲突
