## 1. 跨平台重复出现的「需求模式」（比职业更重要）

论坛里真正稳定的，不是「PM 要 PRD 模板」，而是下面 **六种作业模式**。同一人一周内可能切换多种。

| 模式代号 | 用户心里的话 | 公开讨论里的形 | 失败时像什么 |
|----------|--------------|----------------|--------------|
| **P1 一句话碰运气** | 「先做出来看看」 | vibe coding / Lovable·Bolt·一句话落地页 | 好看但改不动、说不清做完没 |
| **P2 边聊边成形** | 「我还没想清，你陪我捋」 | 长 ChatGPT 会话、反复重说 | 上下文丢、前后矛盾、不知哪版作数 |
| **P3 稿→批→再稿** | 「你先出一版我改」 | AI 写 PRD/文案/详情页再人工改 | 同质化、假大空、无法执行 |
| **P4 材料包理顺** | 「我有一堆文档/纪要」 | 多 PDF/飞书/微信记录丢进模型 | 找不到重点、一篇超长不可用 |
| **P5 多线并行交付** | 「大促/出海/多页一起上」 | 运营多活动页、多语言 | 窗口开爆、互相覆盖、不知谁好了 |
| **P6 要可验收结果** | 「怎样算做完？客户能点到吗？」 | 验收清单、对照 PRD、截图 | 进程绿了但业务没齐 |

**对 cco 的直接含义**：

- 现澄清相偏 **P2 的考试形态**，但用户要的是 **P2 的对话形态**。  
- Chat 竞品强在 P1–P3 的「生成文字」；弱在 **P5 编排 + P6 对照验收 + 真跑 worker**。  
- cco 差异化应钉在：**计划一等公民 + 可拆可跑可验**，而不是再做一个更会闲聊的 ChatGPT。

## 2. 非开发用户与 AI 协作的「五道坎」（多源交叉）

综合 vibe-coding 讨论、YC 对非技术创始人、卖家文案工具、Spec/Planner 类产品：

| # | 坎 | 用户原话倾向 | 产品若无视 |
|---|----|--------------|------------|
| 1 | **不会开场** | 「需求在哪输？提示词怎么写？」 | 空态像考场或 IDE → 弃用 |
| 2 | **范围爆炸** | 「越聊越多，不知砍什么」 | 无「不做」闸 → 计划不可执行 |
| 3 | **版本迷失** | 「昨天那版更好，在哪？」 | 多轮无「这版作数」→ 不信任 |
| 4 | **生成≠落地** | 「文案有了 / 代码有了，上线仍不会」 | 停在 md 或停在黑盒站点 |
| 5 | **做完无感** | 「Agent 跑完了，业务齐了吗？」 | exit 0 / 无对照计划 |

Charlie Graham 文：非开发 vibe 工具 30 分钟能出像样 landing，但配置表单、真业务接线往往更耗时——**「生成快」≠「事毕」**。  
Simon Willison：vibe coding 原意是 **不管代码、可扔的周末项目**；把一切 AI 辅助都叫 vibe coding 会误导——**认真交付需要读结果、定范围、可维护**。  
YC：没有技术合伙人时，仅靠 no-code/外包/顾问，难撑「可融资技术公司」——对 cco 主受众更实际的承诺是 **业务可验证的交付**（页可点、表可收、流程可走），不是替代 CTO。

**cco 话术边界（对外诚实）**：

```text
帮你：把想法收成可执行计划 → 拆开并行干 → 对照计划看齐不齐
不假装：替你做完整公司技术合伙人 / 一键上市级系统
```

## 3. 分人群：需求是什么样的 · 如何沟通 · cco 如何帮

> 每节：**场景与痛苦** → **沟通原则** → **cco 路径（L/M/H）** → **成功长什么样**。  
> 标「模式综合」处 = 行业常见规律，待访谈验证。

### 3.1 创业者 / 小老板

**需求模式（一手 + 综合）**  
- P1 极强：周末验证、先有个能给客户看的东西。  
- 怕技术合伙人谈判、怕报价开发、又被 YC/圈内提醒「没有技术中台会痛」。  
- 要的是 **可演示的闭环**，不是架构优雅。

**如何沟通**  
- 禁止第一句引擎/仓库/schema。  
- 用结果句：「三天后你能打开一个链接，让客户填表留下线索——我们按这个验。」  
- 主动帮砍：**本周不做**支付/会员/后台。  
- 承认不确定：「你还没想清也没关系，先说客户是谁、他卡在哪。」

**cco**  
- 默认 **L 或薄 M**：一句话 → 短计划 → 快拆/甚至 direct → 看结果。  
- 边聊完善（02）必须顺；问卷不能挡。  
- 验收：人话 done_when + 可选浏览器冒烟（已有能力可开）。  

**成功**：老板能指着屏幕说「这就是我要卖的」；失败时人话重试，不丢堆栈。

---

### 3.2 产品经理

**需求模式**  
- P2/P3/P4 强：PRD、纪要、多需求包。  
- 公开工具向：**把想法结构成 AI 可执行的 Spec/Plan**（BrainGrid、Spec-driven 插件类 Show HN）——说明 PM 痛的是 **「人话 → 机器可派工」**，不是再缺一个聊天窗。  
- 论坛/职场综合：ChatGPT 写 PRD「像样但不落地」——缺 depends、缺验收、缺谁先谁后。

**如何沟通**  
- 尊重「计划文档」心智：目录、非目标、验收、风险。  
- 可以略技术，但默认仍人话；高级折叠。  
- 多需求时先 **索引** 再切多计划（04），对齐十年 PM 收件箱。

**cco**  
- 主路径 **M**；需求包 **H**。  
- 拆分台 = 派工预览；confirm = 立项开跑。  
- 巡检对照计划 = PM 的「有没有按 PRD 做完」。  

**成功**：一份（或一组）计划可给同事读；跑完能勾验收；漏了能回补。

---

### 3.3 设计师 / UI 设计师

**需求模式（综合 + 创造者社区）**  
- 要 **看得见**：版式、层级、组件态；怕「AI 乱改视觉」。  
- 与开发交接痛：口径在 Figma/注释里，执行丢。  
- 部分用 AI 出界面草稿，但仍要 **可点预览 / 走查**。

**如何沟通**  
- 先问「用户第一眼看到什么、主按钮是什么」。  
- 少谈 DAG；多谈「首页三块、表单两步」。  
- 计划里写清 **视觉约束/不要什么风格**（非目标）。

**cco**  
- **L/M**：落地页、说明站、组件文档站。  
- 拆分：文案∥结构∥走查；`browser` 类验收可选。  
- 避免主路径像 CI。  

**成功**：预览或截图级「像设计意图」；问题可单步重跑。

---

### 3.4 运营 / 增长 / 出海

**需求模式**  
- **P5 极强**：多活动、多语言、多表单、多截止日期。  
- 要进度「几路在做、谁卡住」——像管战役不是管 commit。  
- 综合：多版本文案/页，怕互相覆盖、怕译完结构坏了。

**如何沟通**  
- 时间盒：「大促前只上这三页」。  
- 用 **本波** 语言：可一起干的页 vs 必须先统一口径的页。  
- 进度人话：进行中/等待/完成/卡住要醒。

**cco**  
- **M 单页战役** 或 **H 多页本波**。  
- 任务并行 +（未来）计划级排版正中靶心。  
- cost-route：大量 implement 省钱；终检旗舰。  

**成功**：活动日能指认各页状态；对照「表单能收、多语言齐」验收。

---

### 3.5 新媒体 / 自媒体 / 内容创业者

**需求模式（综合 + V2EX 创造者气质）**  
- 选题快、要铅封页/合集页/报名页；预算敏感。  
- P1+P3：先出稿再改调性；怕 AI 味、怕不像人设。  
- 变现页要 **快上**，不是完美架构。

**如何沟通**  
- 用内容语言：栏目、系列、CTA、人设关键词。  
- 「先上一个能放链接的页，再迭代」。  
- 反馈完善：改语气比改技术栈重要。

**cco**  
- **L 为主**，模板起笔；M 若系列站。  
- 计划短；直接执行仅极短说明时可用。  
- 验收：链接可打开、主 CTA 可点、文案像你。  

**成功**：今天能把链接发到简介；明天能改一版再拆步。

---

### 3.6 电商卖家

**需求模式（一手信号：卖家做「稳定文案」工具）**  
- ChatGPT 写详情页 **容易但不稳**：语气跳、参数乱、多 SKU 不一致 → **伤转化**。  
- 要批量、要模板、要「能上架」不是「像作文」。  
- P3 极强：生成→改价促点→再生成。

**如何沟通**  
- 先锁：类目、卖点三句、禁编造参数、必含的规格表。  
- 强调 **一致与可勾选验收**（标题含词、主图位、详情模块齐）。  
- 别谈 agent；谈「上架清单」。

**cco**  
- **L/M**：单品页/活动页；多 SKU 可用 H 切多计划（每品一计划）防长文。  
- 拆分：信息架构∥文案∥合规自检。  
- 省钱 CLI 跑重复劳动。  

**成功**：一页可上架；多品不串味；失败单品可重拆。

---

### 3.7 教师 / 培训老师

**需求模式（综合）**  
- 课件结构、报名、作业说明、学员能打开。  
- 怕技术配置；要 **稳定可复用**（下学期还用）。  
- P2：边备考边改大纲。

**如何沟通**  
- 教学语言：目标学员、一节课学会什么、作业是什么。  
- 验收=学员路径：打开→读到重点→交作业/报名。  

**cco**  
- **L/M**；计划章节像教案而非 PRD 黑话。  
- 少并行也可以，稳更重要。  

**成功**：链接发给学员不丢人；下学期改一章能重跑那一章。

---

### 3.8 企业行政 / 财务 / HR

**需求模式（综合）**  
- 制度页、流程说明、收集表、内宣；要 **存档、少出错、可追责**。  
- 极怕「AI 乱改正式表述」；要强 **不做/必审**。  
- P3+P6：稿件多次审，最后要齐套。

**如何沟通**  
- 强调：确认前不改业务环境；可选步骤可勾掉。  
- 用公文结构：目的、适用范围、流程、附件。  
- 失败说人话，不暴露内部 ID。  

**cco**  
- **M** 为主；confirm 心智是加分项。  
- optional 审批步骤；inspect 对照条文清单。  
- 默认少自动、多闸。  

**成功**：制度可发布；表格可收；全程有确认感。

---

### 3.9 次受众：开发者（只对比，不抢戏）

论坛（HN/V2EX）大量是开发者自嗨工具链。他们要日志、diff、模型名——**cco 提供但折叠**。  
主路径若迎合他们，主受众会觉得「又不是给我用的」。

## 4. 如何与这类人沟通：cco 统一话术层

### 4.1 开场（解决「需求在哪输」）

| 错 | 对 |
|----|----|
| 先选三个抽象入口再找输入框 | **先看见大输入框**：「用一句话说要做成什么，或拖入材料」 |
| 「问题 1/5 主要给谁用」当英雄 | 需要时再问，且像商量不是考试 |
| 引擎、high 默认、路径当主信息 | 主信息=项目名 + 要办的事 |

### 4.2 共情句式（可进 prompt / UI 微文案）

- 「你还没想完全没关系，我们先写到能验收为止。」  
- 「我先按假设写一版，你改三个词也行。」  
- 「这篇先不上支付，只验证客户愿不愿留联系方式。」  
- 「做完的标准是：你能打开页面走通主按钮——不是程序退出码。」  

### 4.3 反馈环话术（P3）

- 你出稿 → **三行摘要**（做成/不做/算完）  
- 用户：**按我说的改** / **这版去拆步** / **换方向**  
- 禁止并列四个同等按钮  

### 4.4 多材料话术（P4/P5）

- 「先做一本目录（索引），再拆成几份能单独交差的计划。」  
- 「不是再写一篇万字，是几份都能单独停、单独验的。」  

### 4.5 绝对避免

- 第一屏 VERDICT / run_id / provider  
- 「你是 worker」「force_serial」  
- 假装用户已确认其实是跳过假设却写成事实  
- 无确认开始改项目文件

## 5. 用 cco 帮他们「实现需求落地」的端到端图

```text
发现（论坛式真实起点）
  P1 一句话 / P2 边聊 / P3 改稿 / P4 材料包 / P5 多线
        ↓  cco 聊天 +（L/M/H）
收成「计划」一等公民（可多份）
        ↓  拆分台：任务波次 · 运行方式人话
确认（唯一开跑）
        ↓  多 CLI：省钱干活 · 强模型想/验（已有路由，人话展示）
对照计划巡检 / 回补
        ↓
用户可感知的「做完」（页可点、表可收、课可上、制度可发）
```

| 用户模式 | cco 部件 | 若缺失用户会去哪 |
|----------|----------|------------------|
| P1 | L 路径、短计划、快验 | Lovable/Bolt/纯 Chat 出静态页 |
| P2 | 主输入第一、当前理解条、digest | 无限 ChatGPT 页签 |
| P3 | 草稿三行+唯一 CTA、replan | 复制粘贴文档地狱 |
| P4 | 附件/材料包、索引 | 飞书+人工目录 |
| P5 | H Bundle、并行叙事、进度 | 多窗口 Agent 互撞 |
| P6 | done_when、inspect、Ensure | 「感觉做完了」或开发验收黑话 |

**cco 相对纯 Chat**：能派工、能并行、能对照验、能省钱分流。  
**cco 相对纯 vibe 站生成器**：有计划边界、确认闸、可重试模块、可多计划战役。  
**cco 相对 IDE Agent**：主受众不进仓库海洋；开发能力次要入口。

## 6. 对已有本波计划的校正（研究 → 决策）

| 原计划 | 田野结论强化点 |
|--------|----------------|
| 01 受众 | 分职业表有效，但 **P1–P6 模式更应驱动 IA**；职业只调例子 |
| 02 迭代 | **P2/P3 是主用户常态**，不是边角；W1 价值被上调 |
| 03 空态 | 论坛式第一痛=开场；W0 仍最高优 |
| 04 多计划 | 对应 P4/P5；运营/PM/大促卖家才高频，可 W2，但话术 W0 可预埋「多需求一起排」 |
| 05 模块化/省钱/验 | 对应 P5 撞车 + P6 做完无感 + 卖家/运营成本敏感；人话总览 > 再造引擎 |

### 6.1 沟通策略产品化（可写进 runtime-prompts 的方向）

1. 按 **P 模式** 选开场，不按职业盘问。  
2. 每条计划强制 **可观察结果 + 不做 + 算完**（已有写作底，要 UI 露出）。  
3. 长会话用 digest，但用户侧叫「到目前我们达成的」而非压缩术语。  
4. H 入口文案用运营/PM 语言「本波要上的几件事」，不用 Bundle。

## 7. 仍建议补的真实访谈（本环境未完成）

因知乎/小红书/Reddit 难抓，**上线前应用 5～8 个真人各 20 分钟**验证：

| 角色 | 必问题 |
|------|--------|
| 小老板 | 上次用 AI 想做什么？卡在哪一步放弃的？ |
| PM | ChatGPT PRD 哪段永远要手改？多需求怎么拆人？ |

## 8. 结论（给产品决策的一页）

1. **主用户的需求不是「会用模型」**，而是六种作业模式 P1–P6 的组合；其中 **边聊/反馈（P2/P3）与做完可感（P6）** 几乎人人有。  
2. **沟通**：结果语言、范围闸、版本作数、确认才改世界；开场必须是大输入而不是考卷。  
3. **cco 落地杠杆**：计划一等公民 + 拆跑验 +（未来）多计划本波；执行层省钱分流已有，要翻译成人话。  
4. **不要**用开发者论坛审美（日志、模型名、Agent 人设）当主路径。  
5. **不要**承诺替代技术合伙人；承诺 **可验收的业务交付节奏**。  
6. 实施序仍建议：**先 03/W0 开场与 CTA（对上第一道坎）→ 02 迭代 → 04/05 多计划战役**。
