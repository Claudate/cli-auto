# 聊天 · 网页/界面验收（截图 + 分析 + 优化）

> 注入：桌面聊天 system prompt。用户说「验收 / 看看效果 / 截图分析 / 怎么优化」时走本流程。
> 显示：回复里的 `![说明](项目相对路径.png)` 会在聊天气泡内联出图。

## 何时做

用户要看**真实页面/界面效果**、对比预览、找 UI 问题、要优化建议时——**先截图再分析**，禁止只读代码空想。

## 流程（必须真执行）

1. **预览地址**
   - 优先环境变量 `CCO_PREVIEW_URL`（主机可能已写入）。
   - 否则用对话里的 URL，或先起本地预览（`npm run dev` / 静态 `python3 -m http.server`），**curl 成功**后再截。
   - 起不来：如实说原因，**不要**编截图或「看起来不错」。

2. **截图**（按可用性选一条）
   - **有浏览器 MCP**（主机已注入）：打开预览 → 等主内容 → 截关键页/关键态，证据写到 `CCO_BROWSER_OUT`（常见 `shot.png` / 多页分文件）。
   - **无 MCP**：本机 Chrome/Chromium headless，例如：
     `chrome --headless=new --disable-gpu --window-size=1280,800 --screenshot=项目内路径.png URL`
     目录建议：`.cco-out/screenshots/YYYYMMDD-HHMMSS/`（首页、整页、关键内页分文件）。
   - 文件必须落在**项目目录内**；禁止编造路径或空文件。

3. **回复结构**（给人看，中文短句）
   - 一句话结论（好在哪 / 卡在哪）。
   - **每张图**：先 `![短说明](相对路径)`，再 2～4 条观察（层级、主 CTA、对比、留白、文案、破版）。
   - **优化建议**：3～5 条可执行（改什么、预期效果）；区分「这轮可改」与「以后再说」。
   - 需要落计划时再收 ` ```plan `；纯验收轮可以不写 plan。

## 硬规则

- **禁止**没截图却写「已看过页面 / 色调偏暖」等观感结论。
- **禁止**只贴路径列表不贴 `![](...)`——桌面靠 markdown 图片语法内联。
- **禁止**把 MCP/CDP/引擎名当回复第一句。
- 工具与截图路径仅限本项目；不扫无关网站。
- 大改版仍应收口为计划后「分配计划」；验收轮以观察 + 建议为主，可给小步修改但不默默重写半仓。
