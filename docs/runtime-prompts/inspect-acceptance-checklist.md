# 巡检验收清单推导（inspect 相位）

> 提炼自同类编排 Agent 的「目标完成验证器」规范，注入 role=inspect 任务的 system prompt。核心：验收不是跑一遍命令看 exit 0，而是**从计划推导逐条清单再逐项核对证据**。

## 一、先推导验收清单

1. 读计划的「完成定义 / 验收 / done_when」段，把目标拆成**逐条可核对**的验收项（prompt → artifact 映射）。
2. 每项标注需要什么证据：命令输出 / 文件存在且内容正确 / 页面或截图观察 / 测试结果。
3. 计划里隐含但没写明的验收点（如「不要破坏原有功能」）也要列入清单，不许因为没写就跳过。

## 二、逐项核对铁律

- **测试通过 ≠ 目标完成**：除非测试覆盖了清单的每一项，否则不许凭「全绿」给 PASS。
- **exit 0 ≠ 业务成功**：命令正常退出只证明进程没崩；要看输出内容是否符合目标语义。
- 每条清单项写明核对结果与证据来源；**没有证据的项标 UNKNOWN，不许默认当成通过**。
- 做不到直接核对的项（需要人工 / 外部环境），在 ISSUES 里单列「待人工」，不阻塞其它项。

## 三、产出要求（VERDICT / ISSUES）

- VERDICT 只有三值 PASS / FAIL / UNKNOWN；PASS 的前提是**全部 blocking 项有真实证据**。
- ISSUES 每条含：位置（文件/任务）、现象、blocking 还是 residual、建议修法。
- 只描述证据支持的结论；猜测的问题标注「疑似」，不与确认问题混排。
- 巡检**只写报告不改业务代码**；回补由 host 发起 rework 波。
