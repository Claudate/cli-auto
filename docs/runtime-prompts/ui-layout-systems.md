## 排版与信息结构（按网站类型选型）

目标：先定**站点类型**与**信息骨架**，再叠色/字/动效；骨架稳，**表现有受控变化**，避免千站一面、死板模板感。  
避免把营销长页、博客、后台、作品集套成同一种「五段 Hero」；也避免无骨架的乱堆块。

### 1. 先选站点类型（写进计划「建议技术」）

| 类型 id | 用户话术线索 | 信息目标（一句话） | 默认对齐 |
|---------|--------------|--------------------|----------|
| **marketing** | 出海落地页、SaaS 介绍、转化 | 3 秒懂给谁 + 主 CTA | `examples/marketing-landing-reference/SPEC.md` |
| **portfolio** | 作品集、个人站、案例墙 | 先见作品再信人 | 本表 §3 |
| **content** | 博客、文档站、帮助中心、百科 | 扫读 + 找文 | 本表 §3 |
| **ecommerce** | 商品详情、店铺首页、清单 | 货 + 价 + 下单路径 | 本表 §3 |
| **dashboard** | 后台、控制台、数据台 | 任务效率、少装饰 | 本表 §3 |
| **app-shell** | 登录后 Web 工具、SPA 壳 | 导航稳定 + 主工作区 | 本表 §3 |
| **story** | 品牌故事、文旅/山水叙事 | 情绪与节奏，转化次之 | 本表 §3 |
| **event** | 活动/发布会/报名页 | 时间地点 + 报名 CTA | 本表 §3 |
| **waitlist** | 未上线预热、邮箱收集 | 一屏说清 + 留资 | 本表 §3 |

用户说「默认/你定」：出海/产品介绍 → **marketing**；作品 → **portfolio**；登录后办事 → **app-shell**；山水文旅品牌 → **story**（可叠 marketing 底 CTA）。  
**禁止**：dashboard 硬套 marketing 五段深底 CTA；marketing 硬套侧栏后台布局。

### 2. 全局信息纪律（所有类型）

1. **一页一主任务**：主 CTA 动词唯一；次 CTA ≤1。  
2. **F/Z 扫视**：关键信息在首屏上半；勿把主按钮沉到第三屏才出现（dashboard 例外：主操作在工具栏）。  
3. **层级 ≤3**：页面 / 区块 / 组件；同屏新概念 ≤3（对齐产品心智）。  
4. **栅格**：桌面 12 栏或 max-width 容器（常见 1120–1280px）；间距用 4/8 倍数；区块垂直节奏统一（如 64/80/96）。  
5. **窄屏**：单列优先；导航可折叠；主 CTA 仍可达；表格可横滑勿挤碎。  
6. **中文**：标题 `text-wrap: balance` 或人工断句；正文行宽约 30–40 字舒适（过宽难读）。  
7. **底部分层**：有「销售底带」时必须与 Footer 不同色/分隔（marketing/event）；dashboard 通常无销售底带。  
8. **与其它体系**：色系 kit + 字体包 + 动效档 **服务**本类型，不反过来决定类型；整包默认见 `ui-delivery-recipes.md`。  
9. **骨架固定 · 表现可变**：必须区块与主 CTA 语义不可丢；**可选区块、左右镜像、疏密、装饰**在白名单内变化（见 §2.1）。禁止「每一页同一套三等分卡片 + 同一 Hero 左右文图」。  
10. **图片位**：各类型关键槽按配方 §3 填实图（Hero/作品/证据）；禁止占位图冒充完成。

### 2.1 受控变化（防死板 · 有随机但不乱）

原则：**信息契约固定，视觉配方抽签**。同一站点类型下，不同项目应看得出「同一类站」，但不应像复制粘贴。

#### 固定（不可随机掉）

| 固定项 | 说明 |
|--------|------|
| 站点类型 | marketing / portfolio / … 不混壳 |
| 主任务 + 主 CTA 动词 | 首屏或工具栏必须可指认 |
| 必须区块的**存在** | 如 marketing 的 Hero、能力、底带/Footer（按类型表） |
| 门禁与可读 | 无占位图、底带≠footer、reduced-motion、窄屏可达 |

#### 可抽变体（每个项目选 2～4 项，写进计划「版式变体」）

从下表**抽签**，勿全选、也勿全不选（全不选 = 死板；全选 = 花）。

| 维度 | 变体选项（择一或组合） | 禁止 |
|------|------------------------|------|
| **Hero 构图** | A 左文右图 · B 右文左图 · C 居中叠图 · D 全幅底图+前景字 · E 上字下产品条 | 主 CTA 消失；字压在不可读图上无遮罩 |
| **区块节奏** | 证据在能力前/后互换；场景与对比二选一；插一句引用/数字条 | 删掉全部证据又自称 SaaS 可信 |
| **栅格密度** | 疏（大留白）· 中 · 密（dashboard 偏密）；卡片 2 列/3 列/错落 1+2 | 无网格乱飘；间距忽大忽小无 token |
| **图文交替** | 奇偶屏左右对调；全宽一条打断两卡 | 连续 4 屏完全同一左右比 |
| **装饰口音** | 细分割线 · 轻纹理 · 单色几何 · 国风雾/线（story）· 无装饰 | 每屏一种完全不同装饰语言 |
| **能力区形态** | 三卡横排 · 纵向时间线 · 左列表右细览 · 两卡+一大 | 超过 5 张无主次 |
| **顶栏** | 实心 · 透明滚后实心 · 极简仅 Logo+CTA | 导航项 >5 还加巨 Logo 双名 |
| **页脚** | 单列 · 多列链 · 极简一行 | 页脚再塞主 CTA 大按钮（marketing 默认） |

**如何「随机」（可复现）**

1. 用项目名 + 日期或用户一句话作 **seed**（例：`hash(项目名) % n` 心里选，或计划里直接写死选项字母）。  
2. 计划「建议技术」写：`版式变体：Hero=B · 能力=时间线 · 密度=疏 · 装饰=细线`。  
3. 实现时**只实现写明的变体**，不要中途再随机改结构。  
4. 用户说「活泼/别太模板/多点设计感」→ 在白名单内 **多抽 1 维**（如错落栅格或全幅 Hero），不升格乱加区块类型。  
5. 用户说「稳一点/商务」→ 少抽：Hero=A、三卡、中密度、少装饰。

#### 按类型：变化幅度

| 类型 | 变化宜 | 变化慎 |
|------|--------|--------|
| marketing | Hero 镜像、证据形态、能力区形态 | 丢掉底 CTA；导航大改信息架构 |
| portfolio | 栅格错落、案例深度 1 vs 2 | 首屏无作品 |
| content | 列表卡片 vs 紧凑行；TOC 有无 | 毁掉阅读栏宽度 |
| story | 章节图文左右、全幅氛围屏 | 硬广五段 SaaS 腔 |
| dashboard / app-shell | 表密度、过滤器位置 | 大改导航心智、加营销 Hero |
| waitlist | 背景与插图口音 | 拆成多页营销长文 |

#### 动效上的「一点随机」（仍受 `ui-motion-effects` 约束）

- 入场 delay **交错**（stagger 40–80ms），不要所有块同一时刻齐出。  
- 同页只用一种 easing 家族；可对次要元素做极轻 float，**主 CTA 禁止漂移**。  
- seed 可决定「要不要」轻粒子/描边，不可叠加超 2 个特效概念。

### 3. 各类型推荐区块顺序

#### 3.1 `marketing` — 营销 / SaaS 落地（默认出海）

| 序 | 区块 | 必须 | 要点 |
|----|------|------|------|
| 1 | 顶栏 | ✓ | 主名 + 导航≤5 + 主 CTA |
| 2 | Hero | ✓ | 结果 H1 + 双 CTA + 示意 |
| 3 | 证据 | 建议 | 数据/截图/Logo 墙 |
| 4 | 能力 | ✓ | ≤3 卡，动作→结果 |
| 5 | 场景/对比 | 可选 | ≤2 路径 |
| 6 | 底 CTA 带 | ✓ | 与 footer 分层 |
| 7 | Footer | ✓ | 链/法务；默认无主 CTA 大按钮 |

真源细节：`examples/marketing-landing-reference/SPEC.md`。  
**变体提示**：序 3↔4 可对调；Hero 用 §2.1 构图 A–E 抽一；能力区勿永远「三张一样高的图标卡」。

#### 3.2 `portfolio` — 作品集 / 个人站

| 序 | 区块 | 要点 |
|----|------|------|
| 1 | 顶栏 | 名 + 作品/关于/联系 |
| 2 | 精选栅格 | **首屏即作品**（2–6 格）；hover 出项目名 |
| 3 | 精选案例 | 1–2 个深度（问题→做法→结果） |
| 4 | 关于短 | 一屏内；技能标签≤8 |
| 5 | 联系 | 邮件/表单；真实联系方式 |
| Footer | 轻 | |

禁止：大段空 Hero 口号占两屏才见作品。栅格：正方形或 4:3，间距一致。

#### 3.3 `content` — 博客 / 文档 / 帮助

| 区域 | 布局 | 要点 |
|------|------|------|
| 列表页 | 顶栏 +（可选）分类 + 卡片/列表 | 标题、摘要、日期；分页或无限滚动二选一 |
| 文章页 | **阅读栏 max ~68ch** + 可选侧 TOC | 字号/行高舒适；代码块可横滑 |
| 文档站 | **左导航 + 正文 + 可选右 TOC** | 当前节高亮；上/下一篇 |

禁止：营销式全宽大字打断长文阅读；正文用书法 display 字。

#### 3.4 `ecommerce` — 店首 / 商品

| 页 | 结构要点 |
|----|----------|
| 店首 | 顶栏（搜/购）→ 主推横幅 1 → 分类入口 → 货架栅格 → Footer |
| 商详 | 图库 \| 标题价库存 CTA（桌面左右；手机上图下信息）→ 详情 Tab → 推荐 |

主 CTA = 加购/购买；价与库存靠近按钮。禁止把结账按钮做成页脚小字链。

#### 3.5 `dashboard` — 后台 / 数据台

| 区域 | 要点 |
|------|------|
| 壳 | 顶栏或侧栏导航（固定）；用户/环境入口 |
| 主区 | 页标题 + 主操作（右上）+ 过滤/表/图 |
| 密度 | 信息密、装饰少；动效档默认 **none/light** |
| 空态 | 表/图无数据时有人话 + 下一步 |

禁止：整页 Hero 营销节奏；禁止底 CTA 销售带默认出现。

#### 3.6 `app-shell` — 登录后工具

| 区域 | 要点 |
|------|------|
| 壳 | 稳定导航（侧或顶）+ 内容路由出口 |
| 主路径 | **一屏主任务**；次要能力折叠 |
| 状态 | loading / 空 / 错 / 成功 均有人话 |
| 设置 | 二级页或抽屉，不抢主路径 |

与 cco 桌面类似：phase 清晰，不堆 IDE 式调试墙。

#### 3.7 `story` — 品牌 / 文旅 / 山水叙事

| 序 | 要点 |
|----|------|
| 1 | 氛围 Hero（大图/雾感 + 短诗意标题） |
| 2 | 章节叙事（2–5 屏，图文交替，忌对称复读） |
| 3 | 体验/线路/亮点卡 ≤3 |
| 4 | 轻转化（预约/咨询）— 可有底带，勿硬广腔 |
| 5 | Footer |

色系常 `shanshui`/`cn-ink`/`jp-wa`；动效 light（SVG/雾）；**少**科技粒子。

#### 3.8 `event` — 活动 / 发布

| 序 | 要点 |
|----|------|
| 1 | 顶栏 + 倒计时或日期条（可选） |
| 2 | Hero：活动名 + 时间地点 + **报名 CTA** |
| 3 | 议程 / 嘉宾 ≤ 可读长度 |
| 4 | 赞助或合作（可选） |
| 5 | 底 CTA 再报名 + Footer |

时间地点必须首屏可见；CTA 文案统一（报名/预约）。

#### 3.9 `waitlist` — 预热 / 候补

| 序 | 要点 |
|----|------|
| 1 | 极简顶栏（Logo） |
| 2 | **一屏**：问题一句 + 价值一句 + 邮箱/表单 + 主 CTA |
| 3 | 可选 3 条权益或产品预览 |
| 4 | Footer 轻 |

禁止五段完整营销站；能一屏完成留资就一屏。

### 4. 布局 token 建议（实现）

```css
:root {
  --layout-max: 72rem;      /* ~1152px */
  --layout-gutter: 1.5rem;
  --section-y: clamp(3rem, 6vw, 6rem);
  --prose-width: 40rem;     /* 阅读栏 content */
}
.container { max-width: var(--layout-max); margin-inline: auto; padding-inline: var(--layout-gutter); }
.section { padding-block: var(--section-y); }
.prose { max-width: var(--prose-width); }
```

卡片栅格：`repeat(auto-fill, minmax(16rem, 1fr))` 或固定 2/3 列断点。

### 5. 与色系 / 字体 / 动效的推荐组合（默认）

| 站点类型 | 色系倾向 | 字体 | 动效档 |
|----------|----------|------|--------|
| marketing | western-saas / nordic | Inter 系 | light→brand |
| portfolio | nordic / custom | 克制；display 仅姓名 | light |
| content | 中性浅底 | 正文可读优先 | none/light |
| ecommerce | brand custom | UI 清晰 | light |
| dashboard | 中性 | UI 字体 | none/light |
| app-shell | 跟产品 | UI | none/light |
| story | shanshui / cn-ink / jp-wa | 标题文楷/明朝 | light |
| event | festive 或 brand | UI + 短 display | light |
| waitlist | 跟品牌 | UI | none/light |

### 6. 写进计划 / 拆分

**建议技术**示例：

```text
- 站点类型：marketing | portfolio | content | …
- 信息结构：首屏任务 = …；主 CTA = …
- 区块顺序：（必须块保留；可选块可删可调序）
- 版式变体：Hero=… · 密度=疏|中|密 · 能力形态=… · 装饰=…（2～4 项，防死板）
- 色系 kit / 字体包 / 动效档：…
```

**成功标准**

- [ ] 站点类型与必须区块一致（非错套后台/营销）  
- [ ] 首屏能回答：给谁、干什么、主按钮是什么  
- [ ] 写明并落地 **版式变体**（≥2 维），非纯默认三卡模板  
- [ ] 窄屏主 CTA 可达；阅读类有合适行宽  
- [ ] marketing：底 CTA ≠ footer（若有底带）  

**拆分 do**：【做什么】写「完成 × 类型信息结构 + 版式变体」；【改哪里】layout/sections；【怎样算做完】对照必须块 + 计划中的变体字母/选项，禁止只写「排版好看」或无变体的复制模板。
