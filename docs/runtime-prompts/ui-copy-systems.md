## 界面文案（开发项目的 UI 字 · 网站/软件/App 必守）

目标：凡是**你正在开发的那个项目**界面上给用户看的字——都要优化到**帮人办事**，不是堆口号、占位句或内部术语。  
**包括**：用户打开的网站、安装的 App、桌面软件、后台、小程序里的标题、按钮、导航、表单、空态、错误、Toast、设置项。  
**不包括**：给开发者看的代码注释、git 说明（可另写）；但用户可见的 release note/更新说明算界面文案。  
与配方/布局配套：先定「给谁、主任务」，再写字；字服务于主 CTA 与主路径。

### 1. 总原则（所有界面）

1. **人话优先**：用户第一句看到的是结果/动作，不是 schema、run_id、VERDICT、堆栈、HTTP 码。  
2. **一屏一主信息**：主标题 1 个意思；同屏新概念 ≤3。  
3. **动词 CTA**：按钮用「做某事」（开始、保存、发送、拆成步骤），少用「确定/提交/OK」除非语境已极清楚。  
4. **主 CTA 文案全产品一致**：同一动作在顶栏/Hero/底带用同一动词短语。  
5. **短**：按钮 ≤ 8 个汉字或 3 个英文词为宜；标题一行优先；说明可两行。  
6. **有下一步**：空态/错误/成功都写「现在可以怎样」。  
7. **禁占位文案**：「点击这里」「Lorem」「测试文字」「TODO」「敬请期待」当成品（除非计划标明演示且非主路径）。  
8. **中英**：出海站主语言跟受众；中英混排时中文用中文标点习惯，英文 UI 用 sentence case（非全大写喊麦）。  
9. **可访问**：图标按钮有 `aria-label`/title；图有 alt（描述内容，不是 “image1”）。  
10. **语气跟配方**：R-ios 克制短句；R-wechat 亲和；R-fintech 稳、勿夸张收益承诺；R-shanshui 可诗意但 CTA 仍清楚。

### 2. 文案角色（网站与 App 通用）

| 角色 | 用途 | 写法 |
|------|------|------|
| **页面/屏标题** | 这是哪 | 名词或短结果句 |
| **导语** | 为什么在这 | 1 句；给谁 + 能得到什么 |
| **主 CTA** | 唯一强动作 | 动词开头 |
| **次 CTA** | 弱动作 | 了解更多 / 稍后 / 跳过（可链可幽灵按钮） |
| **正文/说明** | 补充 | 短段；可扫读 |
| **标签/字段** | 表单项名 | 名词；勿问号堆砌 |
| **帮助/提示** | 防错 | 具体例子，勿空泛「请输入正确内容」 |
| **空态** | 无数据 | 原因 + 一个动作 |
| **加载** | 等待 | 在做什么（可选进度）；勿只转圈无字若 >2s |
| **成功** | 完成 | 结果 + 下一步 |
| **错误** | 失败 | 人话原因 + 可做什么；技术细节折叠/日志 |
| **通知/Toast** | 短反馈 | 一句；勿段落 |

### 3. 网站营销文案（marketing / story / waitlist / event）

| 位置 | 要写 | 禁止 |
|------|------|------|
| Hero H1 | **结果导向**（用了之后怎样） | 空口号「赋能未来」「引领革新」无宾语 |
| Hero 导语 | 给谁 + 场景 + 差异一句 | 功能清单堆砌 |
| 主/次 CTA | 动词；全站一致 | 「点击此处」；主次同强 |
| 证据 | 可感知数字/原话/截图说明 | 假数据装真 |
| 能力卡标题 | 用户动作 → 结果 | 说明书目录腔「模块一」 |
| 底 CTA | 与 Hero 主 CTA 同义或同动作 | 与页脚再塞第三个不同动词强按钮 |
| Footer | 链、法务、次要入口 | 默认再放大主转化钮 |

**公式（可直接套）**

- H1：`让【谁】在【场景】【可观察结果】`  
- 能力卡：`【动词】… → 【可见结果】`  
- 底带：`准备好【结果】了吗？` + 同主 CTA  

**story/山水**：标题可意境；**CTA 与导航仍白话**（「预约参观」「了解线路」）。

### 4. 软件 / App / 后台微文案（app-shell / dashboard / 桌面工具）

| 场景 | 好例子 | 差例子 |
|------|--------|--------|
| 主按钮 | 保存计划、开始运行、添加项目 | 确定、提交、执行 |
| 导航 | 计划、运行、设置 | module_plan、sys |
| 空列表 | 还没有项目。添加一个项目开始。 | 暂无数据 |
| 加载久 | 正在拆分步骤… | （无字） |
| 错误 | 无法连接本机 Claude CLI。请到环境检查后重试。 | Error 500 / panic |
| 权限/危险 | 将删除此会话，不可恢复。 | 警告！ |
| 设置项 | 同时进行几步：控制并行数量 | max_parallel |
| 开关 | 开启后…（一句后果） | 启用 flag_x |
| 成功 Toast | 已保存 | Success |

**桌面/工具产品（含 cco 气质）**：主路径用产品用语（拆成步骤、确认并开始）；高级/系统项默认折叠，文案标明「高级/可选」。

**表单**

- 标签在字段上或前，不靠 placeholder 当唯一标签。  
- placeholder = 示例（`例如：出海落地页`），不是「请输入」。  
- 校验失败：指哪错 + 怎么改（「邮箱需包含 @」）。

**列表/表格**

- 列名人类可读；空单元格用「—」或「无」，不用 null。  
- 批量操作：先说影响几项，再确认。

### 5. 按配方的语气（口音）

| 配方/kit | 语气 | 示例 CTA |
|----------|------|----------|
| R-overseas / western-saas | 清晰、自信、短 | Get started / 免费开始 |
| R-ios / ios-hig | 极简、少感叹号 | 继续、完成 |
| R-material | 直接、辅助线完整 | 下一步、创建 |
| R-fluent | 专业、企业稳 | 登录、开始使用 |
| R-ant / 后台 | 操作精确、少修辞 | 查询、导出、新建 |
| R-wechat | 口语、亲近 | 立即体验、加入 |
| R-shanshui / cn-ink | 标题可雅，按钮须懂 | 探索线路、预约 |
| R-fintech | 克制、无保证收益话术 | 了解产品、预约咨询 |
| R-edu | 鼓励、步骤清楚 | 开始学习、下一课 |
| R-devtool / startup-dark | 准、可技术但主路径仍人话 | 部署、查看日志（次级） |

### 6. 中文排版与用词

- 避免「进行一个…的操作」；改为「…」。  
- 少用「该功能」「用户需」；直接说「你可以…」。  
- 数字与单位不拆行；英文产品名首次可中英，后文统一。  
- 全角标点用于中文界面；中英混排按钮优先短中文或短英文，勿中英重复堆在同一钮（「开始 Start」除非刻意双语产品）。

### 7. 写进计划 / 拆分 / 实现

**建议技术或「文案」小节：**

```text
- 界面语言：中文 | 英文 | 中英
- 语气：跟配方（如 R-ios 克制 / R-overseas 转化）
- 主 CTA 动词：（全站/全App唯一）
- 关键状态文案：空/错/载/成功各有一句草稿
```

**成功标准**

- [ ] 主 CTA 动词全产品一致、人话  
- [ ] 首屏/首屏 App 能回答：给谁、干什么、点哪  
- [ ] 空态与错误有下一步；无 Lorem/TODO 主路径  
- [ ] 无内部 ID 作用户第一句  
- [ ] 图标按钮有可达名称  

**拆分 do**：涉及 UI 的 body【怎样算做完】含文案验收（主 CTA、空错载成功）；禁止只写「界面完成」不写字。  
**实现顺序**：结构定后 **先关键文案再美化**；可与 tokens 并行，但勿先假字后忘改。

### 8. 与其它体系

| 体系 | 关系 |
|------|------|
| layout | 区块有了才写对应槽位文案 |
| typography | display 字只承载短标题文案 |
| color | 错误态色 + 错误文案一起出现 |
| motion | 文案稳定后加动效，勿动画掩盖读不清的字 |
| recipes | 语气跟 R-*；平台配方改口音不改「人话」底线 |
| landing-gates | 假域名/占位图旁也禁止占位文案充完成 |
