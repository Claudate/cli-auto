## 0. 修正后的一句话

**不是「重大决策辅助引擎」或判决神谕，而是：**

> **本机镜子**：用你自己的数据与表述，把不完整的自我认知**外化**——摊开「想成为的自己」与「正在作用的我」之间的缝隙、显性与隐性问题、选项与失去——从而**接近主观渴望**；答案只对你有效，绝不宣称客观最优。

（多视角加压后的同义表述：sense-making of desire under incomplete self-knowledge，不是对共享目标函数做选项排序。）

楼主原话的重心迁移：

| 旧标题偏误 | 修正后 |
|------------|--------|
| 重大决策很难 = 拆小决策、做对每一步 | 难在**知道问题是什么、自己要什么**，发现显隐问题 |
| 像企业战略：数据 → 里程碑 → 逼近客观真实 | **刻意不走**强客观商业决策；那是另一类怪物 |
| 工具给正确答案 | 工具帮你**接近主观渴望**；数据来自自身，结论只服务自身 |
| 所有人都需要 | **不**；来自长期迷茫期的自用/同好需求 |

## 1. 产品本体：你在解决哪一类痛

### 1.1 问题的真正形状

重大**个人**决策卡住时，常见不是「信息不够多」，而是：

1. **议题错了**——问的是「要不要 X」，真实张力在「怕失去 Y / 想成为 Z」。  
2. **自我叙事错了**——脑子里的「我」是理想像，不是正在花钱、害怕、拖延、依恋的那个。  
3. **隐性条款没出场**——关系、身份、面子、身体、时间窗口，决策时不说，事后才爆发。  
4. **误以为存在唯一更优解**——个人题经常是两难粥；需要的是**可接受的不完美**与「我会失去什么」。

工具的价值机制（不是功能清单）：

```text
外部化内心多方声音
  → 对照「想成为的」与「正在作用的」
  → 摊开选项的得/失/恐惧/未决
  → 用户自己认领倾向（不是模型替你认领）
  → （可选）把认领变成可执行的小步
```

这是 **values clarification（价值观澄清）** 在个人生活上的近亲，不是企业 OKR 系统，也不是通用聊天省钱技巧。  
（临床决策辅助里，options / benefits·harms / values 结构已很成熟，见 [OHRI Patient Decision Aids](https://decisionaid.ohri.ca/)；我们**只借结构，不进医疗域**。）

### 1.2 明确放弃的赛道

| 放弃 | 原因（与楼主一致） |
|------|-------------------|
| 公司发展 / 企业目标的「逼近客观」 | 要无数数据与里程碑；不是个体价值聚焦 |
| 替用户证明「客观上正确」 | 个人题无唯一最优；且 AI **改不了**「以为自己做得到」的自我认知误差 |
| 云端决策平台收隐私 | 价值观、资源、世界观**不能**放心交给第三方（seanzhao 第 1 点对 SaaS 致命；对本地开源则变成**架构优势**） |
| 与豆包式「一招省 1k」竞品 | 那是**低摩擦工具性问答**；你的场景是**长迷茫、高主观、要看见自己** |
| 几百万投资家庭的理财顾问位 | 他们不缺顾问；也不是你的信任模型 |
| 营运型平台背锅 | 作者已选开源、同好、不背商业与医疗锅 |

### 1.3 「想成为的自己 vs 真实作用的自己」

楼主洞见：

> 人脑中的自己是自己想成为的样子，而不是自己真实的样子。

工具**可以**：

- 用角色/诉求卡把多方声音**同时**摆上台（安全、成长、关系、现实…）  
- 追问「若选 A，你实际会失去什么 / 谁会失望 / 三个月后早晨什么感觉」  
- 标出**叙事**与**行为线索**的不一致（仅当用户自己提供了日记/过往选择时）  
- 允许「暂缓」「认领不完美」

工具**不可以**：

- 诊断人格障碍或「你真实的你是…」权威判决  
- 用一次会话「揭穿」用户  
- 暗示已完成心理咨询或治疗  

意义无非：**尝试看到各种可能性，接近真实**——动词是「接近」，不是「抵达」。

## 2. 论坛批评如何反过来加固设计（开源本地视角）

seanzhao 四问针对的是**对外营运平台**。作者已回应：开源、个人、不营运。批评**并不作废**，而是改写成设计铁律：

| 批评点 | 对 SaaS 平台 | 对「本机开源 · 接近主观渴望」 |
|--------|--------------|--------------------------------|
| 1 信息含主观与资源，不能交第三方 | 致命 | **必须 local-first**：记忆与会话默认本机；不上传为默认；清除一键可见（精神对齐 [local-first](https://www.inkandswitch.com/local-first/)） |
| 2 AI 解决不了自我认知错误，会背锅 | 致命 | **文案与终点禁止「正确决策」**；强制未决、能力假设清单：「你认为自己做得到的，哪些从未被现实检验？」；用户点「我认领」才结束 |
| 3 贵无人用 / 贱难回本 / 简单题通用 AI 够 | 商业模型问题 | **不卖决策**；简单题引导用户去通用 AI；本工具只服务「想看清自己」的长题 |
| 4 豪门投资不需要你 | 定位问题 | **非用户**写进产品：不碰投顾、不碰高净值咨询位 |
| 运营成本覆盖 | 商业问题 | 开源零营运叙事自洽；**单人维护边界**要极窄（见 §6 可爱机制白名单） |

**真需求可以很小。**  
开源手作的正当性来自：**作者与同好是否反复使用、是否减轻迷茫期的自我欺骗**——不是 TAM。  
「不是所有人都需要」不是弱点，是**过滤器**。

### 2.1 真需求是一层栈，不是单一人设

| 层 | 谁 | 需要什么 | 与本构思 |
|----|-----|----------|----------|
| **L0 核** | 长期说不清「我要什么」的人 | 镜子：接近主观渴望 | **设计缪斯 / 认识论定义者** |
| **L1 邻** | 目标模糊的做事人（含 cco 的 PM/出海） | 想清再写成可核对计划 | 若嫁接任务台，是**高频浅层**；原则仍服从 L0 |
| **L2 域** | 如医患/家属二元（zhangjing） | 多方价值并陈 | 仅能作**参考包想象**；默认不做产品承诺 |
| **L3 非需求** | 豪门资本、冰箱保修、纯事实查询 | 顾问已有 / 通用聊天够 | **硬排除** |

L0 定义「这是镜子不是神谕」；L1 可以借用形状，但**不可用 L1 的执行闭环抹掉 L0 的成功标准**（想清了、决定不做，也算成功）。

### 2.2 最危险的不是「市场太小」，是「混合妄想」

```text
混合妄想 = 个人开源手作
         + 文案听起来像决策权威
         + 心里又按创业平台在长功能
```

seanzhao 对平台的经济学批评，应用来**禁止不小心长成 SaaS 骨架**，而不是用来否定 N=1 手作。  
反过来：若功能只在「假如普通人月付 / 假如千万家庭转化」时才有意义——对这个模式就是噪音。

### 2.3 本地也消不掉的那一刀（批评点 2）

「本机 / 开源」只解决**保管权**（秘密不交给平台），**不解决判断权外包**。  
用户仍会：误报能力 → 漂亮 Brief → 开干 → 失败 → 骂工具。  
因此铁律比「数据在本地」更重：

- 永不承诺正确/最佳/你应该  
- 强制假设、失去、未决、未检验的「我能」  
- 用户自己的价值/约束 vs 模型假说 vs 外部事实 **三分来源、界面可区分**  
- 只有人的确认/认领才算提交

## 3. 伦理与硬边界（含医学旁注）

### 3.1 必须永不宣称

- 医疗：手术做不做、用药、预后判断  
- 法律 / 移民 / 税务定论  
- 投资建议、收益承诺  
- 「这是你客观上该选的」  
- 「AI 已理解真实的你」

### 3.2 医学博士的二元辅助决策（zhangjing）

[Shared decision making](https://www.ahrq.gov/sdm/about/index.html) 的正统是：**医患（+家属）协作**，证据 × 临床专长 × 患者价值观。  
AI 可做的至多是**澄清选项与价值**，不能在医生建议与工具建议对立时**当裁判**。

对本构思：

| 判断 | 说明 |
|------|------|
| **同构可学** | options / 利弊 / 价值权重 / 家属另一声音 |
| **产品上默认不做** | 医疗 SDM 是另一合规宇宙；开源个人小项目**背不起**「工具说不做手术」 |
| **若未来有人 fork** | 必须进专业伦理与免责框架；**不是**本构思主线 |

一句话对医学旁线：**可以参考结构，不要合并产品。**

### 3.3 减轻「背锅」的诚实机制（比免责声明更真）

免责声明几乎没人读。更有用的是**交互形状**：

1. **终点是 Brief，不是 Verdict**——页面标题「你的澄清稿」，不是「决策结果」。  
2. **每个选项强制「失去 / 未检验的能力假设」**。  
3. **「我认领」按钮**由用户点；AI 只给倾向草稿且默认折叠。  
4. **能力校准问**：「若失败，最早会在哪一步发现？那时的你还认这笔账吗？」  
5. **高风险域检测**（辞职可；手术/自杀意念/犯罪 → 拒答并导向真人帮助，不做多轮扮演）。  
6. **双人模式（家属）**若做，必须显式「两套价值观并陈」，禁止合成「家庭正确解」。

## 4. 可爱机制白名单（服务「接近主观渴望」才留）

工程草稿里的多代理、主持人评分、测题、向量日记——**全部降级为候选**；只有服务本体才进白名单。

### 4.1 核心（构思上不可丢）

| 机制 | 为何可爱 |
|------|----------|
| **苏格拉底式反问槽** | 直接打「问题是什么 / 我要什么」 |
| **诉求角色组（内心多方）** | 把理想像拆成可对质的声音；不是 Worker 工种 |
| **得 / 失 / 恐惧 / 未决 强制结构** | 决策可视化；接受不完美 |
| **有界对话 + 人闸** | 对抗过程可视、可停；防无限表演 |
| **本机记忆与预判条** | 数据来自自身、跨次接近；非云端画像生意 |
| **Brief 作为合法终点** | 个人决策常**不必**进入「拆任务开跑」 |

### 4.2 可有可无（易过度设计）

| 机制 | 态度 |
|------|------|
| 主持人 AI 自动打分 | 未验证前不进默认；人闸已够 |
| 五套以上会话规则（互助会/倾诉…） | 先一种深谈 + 一种短澄清 |
| 心理测题库 | 可选；不挡入口 |
| 日记/录音向量人格 | 高敏 + 高预期；构思上后置；摘要即可不向量 |
| 评分最高 AI 全文总结 | 改为**冲突地图 + 用户认领**；高分只作加权提示 |

### 4.3 与「多轮对抗」的关系（保留精神、收紧野心）

楼主原设想（轮次检查点、创造价值、干预）仍然成立，但在**新标题**下重新解释：

- 对抗的对象不是「客观事实」，而是**内心不同渴望与恐惧**  
- 「创造价值」= 是否让用户**更看见自己**，不是是否更像正确答案  
- 终局不是「赢的一方」，是**并陈后的认领**

## 5. 结合本仓 cco：地形对齐分析（主章）

> 本章钉死 **cco 真实产品与代码**，不再空谈「一般决策工具」。  
> 真源：[`PRODUCT.md`](../PRODUCT.md) · `app::{chat,split,run}` · `state/sqlite` · 桌面 `web/js/features/{chat,split,project}`。

### 5.1 cco 今天到底是什么（不可美化）

| 维度 | 本仓事实 |
|------|----------|
| **一句话** | 本机轻量 **任务控制台**：写计划 → 拆开 → 并行干 → 对照验收（[`PRODUCT.md`](../PRODUCT.md)） |
| **主受众** | PM / 出海 / 非开发业务负责人——心智三问是**项目 / 计划 / 跑得怎样**，不是「我是谁」 |
| **主循环** | ① 生成 plan.md → ② 核对 → ③ Mode B 拆分 → ④ Scheduler+Worker → ⑤ Inspect/回补 |
| **硬契约** | **唯一业务开跑** = `app::split::confirm`（桌面 `confirm_start`）；聊天 **禁止** spawn worker（`app/chat` 文件头写死） |
| **计划从哪来** | 已有 `.md` **或** 聊天共建 → `save_plan` → `plans/*.md`（见 Mode B 文档） |
| **聊天实际能力** | 多轮 NL + system 软澄清（目标/范围/约束/验收/风险）+ ` ```plan ` fence → draft → 用户保存；**无**槽位状态机、无 Brief、无角色对抗、无跨会话画像 |
| **会话存储** | `{project}/.cco/chat/*.json`，约 48h TTL——**不是**长期用户记忆 |
| **SQLite 今天** | `~/.cco/cco.db`：`plan_jobs` / `plan_tasks`（过渡）+ **`cco_split_*` 拆分 SoT**；**无** user_profile / guide_session |
| **「角色」一词** | 已有含义 = Worker **路由** `provider/role/scope`（多 CLI 协作），**不是**内心诉求代言人 |
| **人闸** | 拆分台默认停 + optional 勾选；`confirm` = **开跑**，不是「认领人生倾向」 |
| **架构分层** | Presentation → `app` → domain；新能力应 `domain/*` + `app/*` + port，禁止堆 `services` 上帝文件 |
| **体验现实** | 非开发主路径仍在修（入口/减法）；主受众体感问题在「任务台清不清」，不在「人生迷茫」 |

**对照「接近主观渴望」：**

```text
渴望仪器成功：我想清楚了（可以不做事）
cco 成功：    计划写清了 → 拆开跑了 → 对照计划做完了
```

这是两种成功函数。混用而不改文案，会同时辜负小陈故事板和迷茫期作者。

### 5.2 同源点：为什么「好像能合」

下列能力是**结构同构**，所以容易产生「塞进 cco 就行」的错觉——同构 ≠ 同一产品。

| 渴望侧机制 | cco 已有近亲 | 同构程度 | 关键差异 |
|------------|--------------|----------|----------|
| 先想清再行动 | 聊天只写 plan、不直接开干 | 高 | 想清的对象：人生渴望 vs **要干什么** |
| 反问澄清 | `cli_call.rs` system：「澄清目标、范围、约束、验收、风险」 | 中 | 软 prompt，无槽位/无强制「失去/未决」 |
| 人闸 | optional + 停拆分台 + confirm | 高 | 闸的语义是 **include/开跑**，不是 **认领倾向** |
| 本机、非云 SaaS | 本机 App + `~/.cco` + 项目目录 | 高 | seanzhao 的信任批评：cco **已选对侧** |
| 结构化输出 | plan fence；CcoSplit 字段；PlanIR | 中 | 输出是**可拆任务**，不是价值观澄清稿 |
| 多「角色」 | Worker role/scope；未来拆分 Agent | 低（易混名） | 执行路由 vs 内心多方 |
| 记忆 | SQLite 存 job/task；chat JSON 短会话 | 低 | 无「上次你卡在…」预判条 |
| 有界多轮 | chat 多轮；inspect rework ≤2；planner 单次+可选 critic | 低 | 无辩论检查点、无价值评分 |
| 可执行小步 | ③④⑤ 整条链是世界级强项（相对渴望工具） | — | 仅当用户**已认领并要做事**才该接上 |

**结论：** cco 最强的是 **「认领之后的计划闭环」**；渴望仪器最强的是 **「认领之前的自我外化」**。  
接合点天然在：**Brief/认领 →（可选）plan.md → 既有 Mode B**。  
错误接合点：把 Scheduler/拆分台改成人生对抗剧场。

### 5.3 冲突点：硬怼 PRODUCT 与架构的地方

| # | 冲突 | 本仓表现 | 若强行合并会怎样 |
|---|------|----------|------------------|
| 1 | **心智三问** | 项目 / 计划清不清 / 跑得怎样 | 第一屏变成「你渴望什么」→ 主受众劝退；违反概念预算 |
| 2 | **主循环唯一** | 旁路不能改写五步序 | 「引导相」可以**插在 ① 前**，但不能**替换** ③–⑤ 叙事，更不能让 D 成立 |
| 3 | **聊天契约** | `app::chat` 只写散文 plan，不 spawn | 可加追问/Brief，**仍不得**从 chat confirm 开跑——与渴望侧「不急着执行」一致，这是**友好冲突** |
| 4 | **confirm 语义** | 唯一业务开跑 | UI 若写「确认我的选择」会像人生背书；必须维持「确认并开始（执行任务）」 |
| 5 | **role 词冲突** | multi-cli role = Worker 路由 | 诉求角色必须另名（`need` / `voice` / `诉求`），禁止占用 `task.role` |
| 6 | **成功指标** | 巡检对照计划 | 「决定不跑」在 cco 里今天是**失败或未开始**，在渴望侧是**成功** → 指标不能共用 |
| 7 | **会话 TTL** | chat 48h 清 | 渴望记忆要跨月；不能复用 chat JSON 当 SoT，应另表或另产品 |
| 8 | **体积与概念** | 同屏新概念 ≤3；文件硬上限 | 角色对抗+主持人+测题+向量一次塞进桌面 = 直接违反轻量与体积 |
| 9 | **非开发体验债** | 任务主路径体感仍未过门 | 再叠人生仪器 = 两头不讨好；工程注意力应优先任务台，除非分仓 |
| 10 | **医疗/伦理** | 无 SDM 框架 | 仓内若出现手术类包，责任模型与 PRODUCT 完全不匹配 |

### 5.5 用故事板对齐：小陈 vs 迷茫作者

**小陈（PRODUCT 故事板）**

```text
选项目 → 聊日语落地页 → 改成功标准 → 分配 → 看进度 → 巡检回补
```

她需要的「澄清」是：**范围、验收、风险、可拆任务**——system prompt 已在做弱版。  
她**不需要**马斯洛角色互撕，除非她主动说「我在纠结做不做这个项目」。

**迷茫作者（论坛本体）**

```text
说不清要什么 → 多方声音 → 得/失/未决 → 认领 → （常常到此结束）
```

她**不需要** CcoSplit 波次与 Worker 并行，除非认领后变成「我要做的三件小事」。

**本仓结合策略（构思结论）：**

1. **默认服务小陈**：① 生成前可加「任务向」引导（范围/验收/失去/非目标），语言仍是项目话。  
2. **迷茫路径不默认**：不进欢迎第一屏；不改心智三问；若做，是折叠入口或姊妹壳。  
3. **共用本机与闸门哲学**：local-first、人确认、不神谕——两边一致，也是 cco 相对云平台的既有优势。  
4. **执行链独占 cco 品牌**：拆/跑/巡检不要被渴望叙事重新定义。

### 5.6 与 seanzhao 批评：本仓已经答了哪几刀

| 批评 | cco 现状 | 仍缺 |
|------|----------|------|
| 隐私不交第三方 | 本机 App + 本地 state；非多租户画像 SaaS | 若 chat 走云端模型 API，**判断内容**仍出域——BYO key / 透明提示可加强 |
| 背锅 | 不做「正确决策」产品承诺；confirm 是开跑不是人生判决 | 文案若出现「AI 建议你…」仍会滑 |
| 成本/营运 | 个人/开源向工具链；非订阅读秒决策 | 引导仪式过重会输给通用聊天（与豆包例同类） |
| 简单题 | 快路径：已有计划 / 一句话聊天出 plan | 需明确：混乱才深引导 |

### 5.7 姿态选择（结合本仓后的收敛）

| 姿态 | 结合本仓后的判断 |
|------|------------------|
| **A 仅任务澄清** | **与 PRODUCT 最同构**；把「失去/未决/非目标」写进计划章节即可增益 ①；心爱的人生镜子被压缩 |
| **B 双人格同 App** | 技术上可行（guide 旁路 + Brief-only），但 **web 概念预算与非开发体验债** 目前扛不住两套主叙事 |
| **C 姊妹思想** | **心爱本体最干净**；cco 继续当任务台；思想与部分 schema 想象可共享 |
| **D 改写 cco** | **否决**：直接违反 PRODUCT 主受众与五步 |

**结合本仓的推荐（仍是构思，不是开工令）：**

> **主叙事保持 A 的纪律（cco = 任务控制台）。**  
> **心爱的「接近主观渴望」按 C 写清本体，不抢 cco 首页。**  
> **若将来代码相会：只允许「任务向 Guide 加强 ①」+「可选 Brief→plan 桥」；禁止 D，慎 B。**

一句话仍成立，且更贴本仓：

> **渴望仪器是灵魂命题；cco 是已落地的任务身体。**  
> 身体可以多练「写计划前想清楚」；灵魂不必穿上 Scheduler 的制服。

### 5.8 若只做「对 cco 真正有用」的子集（思想优先级）

不排期，只按**对本仓主受众 ROI** 排序：

1. **计划章节契约**：目标 / 非目标 / 约束 / **会失去什么** / 验收 / 风险——加强 ①，几乎不改架构。  
2. **聊天软→硬一点**：信息不足时不急着 fence；缺槽位时追问（仍无人生角色剧）。  
3. **项目级短记忆**（可选）：同项目上次计划的约束/未决，空态一行——用 SQLite 新表，不污染 `cco_split_*`。  
4. **Brief 中间态**（可选）：保存 plan 前一页「得/失/未决」核对——服务小陈也服务轻量纠结，不必马斯洛。  
5. **内心多方 / 人生 Pack**：对本仓主路径 ROI 低、概念成本高 → **不要**当作 cco 近场必做。  
6. **主持人评分 / 向量人格 / 医学包**：与本仓无关或有害 → 排除。

### 5.10 若硬缝进 cco：结构张力（预警）

| 张力 | 说明 |
|------|------|
| 关怀对象 | 人生渴望 vs 要交付的项目 |
| 成功指标 | 更知道自己要什么（可**不跑**）vs 计划跑完巡检绿 |
| 受众 | 迷茫同好 vs PRODUCT 的 PM/出海 |
| 语言渗色 | 拆分/完成的「客观步」渗进 Brief，把主观澄清变成默认可执行政策 |
| **confirm 误读** | `confirm` = 业务开跑闸；若 UI 不拆清，会被读成**人生选择背书** |
| 辩论滑梯 | 有界多角色 → 治疗/人格 OS，违反轻量 |
| **role 词** | Worker role 被诉求角色污染 → 混跑路由灾难 |
| **体验债** | 任务主路径未过门时叠第二叙事 |

嫁接底线：**Brief 冻结 ≠ Run 确认**；两条闸，两套文案；chat 永不旁路 confirm。

## 6. 冷启动与数据伦理（个体价值版）

楼主冷启动设计在新本体下的读法：

| 入口 | 在「接近渴望」下的意义 |
|------|------------------------|
| **快开始** | 问题扩散 + 少画像；适合「有点乱但还不想挖太深」 |
| **反问** | 主路径：数轮丰富「问题/要什么/失去」 |
| **测题** | 辅助槽位，不是人格判决书 |
| **生活记录导入** | 用**自己的历史**逼近真实自我；最高敏感 → 本地、可删、默认可不做向量 |

首日 0 数据不可耻：  
**迷茫期用户往往说不清**——工具的第一份礼物是「问题开始成形」，不是「画像完整」。

## 7. 角色组在本体内的位置

「核心利益」用词可弃；保留结构：

**角色 = 内心诉求的代言人**，不是专家顾问厅。

- 安全 / 成长 / 关系 / 自我实现 / 现实事务 —— 经典、好懂  
- 感性组（欲望、恐惧、依恋、自我）—— 挖理想像与恐惧  
- 理性组（规划师、市场…）—— **更适合任务 Pack**；在个人渴望主线里应降噪，避免又滑回「客观正确」

辞职例仍然经典：不是五人开会投出真理，而是**五股力在你身上拉扯**被看见。

## 8. Brief：合法终点（比计划更贴本体）

对个人渴望工具，**成功会话可以不产生 plan.md**。

澄清稿最小结构（思想契约，非 schema 工期）：

```text
议题（用你的话重述）
我想成为的 / 正在作用的（对照，可空）
各方诉求（代言人 → 一句话）
选项（含「暂缓」「维持现状」）
每选项：得到 · 失去 · 恐惧 · 未检验的「我能」假设
未决与需现实检验的一步
我认领的倾向（用户填，可改可空）
```

「倾向建议」若由模型起草：**必须标为草稿**，且低于「我认领」。

## 10. 仍未解开的问题（诚实留白）

1. **自用够不够开源？** 同好是否真的与「长期迷茫」共振，还是只点赞不打开？

5. **cco 代码库是否终有一天承载它**，还是永远姊妹仓？构思期允许双轨想象。  
6. **危险内容与强制转介**的具体阈值谁来定？  
7. **角色组过多是否重新制造表演性自我**（用角色剧本逃避真实感受）？

## 13. 竞品重新框定（避免打错架）

不是「决策 SaaS 创业公司」，而是：

| 竞品 | 它赢在哪 | 你应赢在哪 |
|------|----------|------------|
| 通用聊天（豆包/ChatGPT/Claude） | 低摩擦、简单题秒回 | 聊天**太薄**时：结构、记忆、得/失/未决、不急着给答案 |
| 纸笔日记 | 私密、零模型幻觉 | 多方声音并陈、冲突地图、可复盘结构 |
| 咨询/治疗 | 真人关系与伦理框架 | **不是**替代；贵或不可及之间的自助澄清 |
| 什么都不做 | 零成本 | 减少「事后发现自己骗自己」的代价 |

README 气质（幻想句）：**当聊天太薄、咨询太重时，本机澄清仪器。**
