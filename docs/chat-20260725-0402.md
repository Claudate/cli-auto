# 模糊聊天 → 可执行需求/计划（cco 澄清相 · vibe-check 子集）

## 目标
- **给谁**：产品经理、出海/运营、非开发业务方（次服务：会用 AI 的初创 builder）
- **场景**：只有一句模糊想法时，先变成**真问题 + 范围 + 验收**，再落成可分配的 plan.md
- **可观察结果**：
  1. 模糊输入不会立刻空心出稿；缺槽时先问 ≤5 题（带 A/B/C）
  2. 三入口可选：想清楚再说 / 从想法到计划 / 已想清直接写计划
  3. 产出 **Brief（澄清稿）→ 用户认领 → plan.md**；**认领 ≠ 开跑**
  4. 计划含目标 / 非目标 / 会失去什么 / 验收 / 风险 / V1 边界，可直接「分配计划」

## 范围
### 做
- 在既有**聊天写计划**链路上加 **澄清相（Clarify）**
  - 挂载：`app::chat` / `web/js/features/chat` / `docs/runtime-prompts/chat-plan-writing.md` + 可选新 prompt 片段
- **三入口路由**（中文产品话，对齐 vibe-check on-ramps）：
  - **想清楚再说**：只产出 Brief，可不落 plan
  - **从想法到计划**（默认）：澄清 → Brief → plan fence
  - **已想清，直接写计划**：跳过盘问，仍强制最小章节（目标/不做/验收）
- **槽位契约**（最小必需）：目标对象、痛苦时刻、可观察结果、明确不做、怎样算做完  
  - 可选：竞品/替代一句、首批用户从哪来
- **追问 UX**：≤5 题；编号 + A/B/C；用户说「直接出计划 / 你定」可跳过并写假设
- **Brief 中间态**：一页可扫读——问题 · 给谁 · 做/不做 · 得/失 · 证据标签 · 未决 · 验收 · V1  
  - 主按钮 **认领并写成计划** → 只写草稿/plan；**禁止**调 `confirm_start`
- **空心计划门禁（不拦）**：缺验收/非目标时黄条提醒（对齐主观渴望子集 D0 思路）
- **证据轻标签**：假设 / 用户原话 / 自用痛点 / 竞品缺口（不强制外网爬取）
- **V1 范围闸**：任务大纲默认只写 V1；V2/Later 折叠一节
- **文档**：能力边界、与 PRODUCT 五步关系、与 D0–D2 / guided 全量关系

### 不做
- 不整包移植 vibe-check（Crazy 8 HTML 引擎、ODI 全量打分、交互式 PRD 站、Checkup Mode、构建期 Git 教学）
- 不做云端用户画像 / 创业验证 SaaS / 医疗法律投顾
- 不做人生 OS、多方内心剧场、主持人自动评分（guided G0–G4 全量另轨）
- 不旁路 `confirm_start`；聊天仍 **禁止 spawn worker**
- 不改 Scheduler / 拆分图格式 / 第二套 Planner
- 不默认联网挖论坛；外部证据由用户粘贴或后续可选增强

## 用户与场景
- **主受众**：拿着模糊业务想法、要推进落地的 PM/出海同学
- **主路径 ≤5 步**：选入口 → 答几题（或跳过）→ 看 Brief → 认领成计划 → 分配计划
- **故事**：小陈说「想做一个提醒浇水的小工具」→「从想法到计划」→ 问清给谁/失败了怎样/不做智能园艺社区 → Brief 认领 → plan 含演示深度与验收 → 分配执行

## 建议技术
- 配方：**R-tool**（本机工具壳；非营销站）
- 交付深度：**D · 改现有**（冻结 Rust + Tauri + 现 web；只挂澄清相）
- 形态：桌面 App 聊天主窗增强 + 本机会话/meta 轻状态（槽位可进 session meta；长期记忆复用 pin/summary）
- 语言/框架：既有 **Rust services/app** + **web/js features/chat**；澄清策略优先 **prompt + 少量 domain 纯函数**（缺槽检测）；JS 不写业务策略
- 架构：**轻分层**；Brief 是 Presentation 产物，不是 PlanIR
- 站点类型：不适用落地页；UI = **app-shell** 内聊天/中间页
- 版式变体：澄清卡片 = 顶进度（可选）· 问题单列 · 选项芯片 · 密度=中；Brief = 分组列表感；无营销 Hero
- 色系 kit：跟现有 cco 壳（不另起第二套）；强调色仅用于「未决/风险」
- 字体：跟现有 UI 栈
- 界面文案：
  - 主 CTA 动词（澄清相）= **认领并写成计划**；全产品后半段仍用 **分配计划**
  - 语气：克制、教练感，非审讯；禁止 VERDICT/run_id 第一句
  - 空：「还没开始澄清。用一句话说你想做成什么。」
  - 错：「这轮没问清楚。可以换个说法，或点『直接出计划』。」
  - 载：「正在整理你的想法…」
  - 成功：「澄清稿已认领，已写入计划草稿。下一步可分配计划。」
- 动效档：**none/light**（仅卡片切换 transition）；库：无
- 图片：无营销大图；空态线标（Lucide）
- 后端：无新 HTTP；复用本机 chat_send / save_plan
- 部署：随桌面 App
- 为什么：vibe-check 验证了「先做对的事」；cco 只需其**轻量澄清子集**接到已有 plan→split→run，避免做成第二产品

## 改完后软件体感（验收对齐）
- 仍是任务控制台：聊天 → 计划 → 分配 → 跑；**后半段五步不变**
- 前半段从「空心生成」变为「澄清 → 认领 → 计划」
- 界面无大 Hero / 无粒子 / 无创业看板整站；澄清单列 + Brief 分组列表
- 黄条提醒缺验收/非目标，**不硬拦**保存与分配

## 任务大纲
1. **契约与路由**：定义槽位 JSON/meta、三入口枚举、与 chat session 状态机衔接；缺槽检测纯函数（domain）
2. **Prompt / 写作策略**：扩展 `chat-plan-writing`（或并列 clarify 片段）——澄清相话术、≤5 题、A/B/C、「你定」写假设、V1 闸、Brief 结构、plan 最小章节
3. **聊天 UI**：入口选择；澄清卡片（进度可选、选项芯片）；跳过/直接出计划；空/错/载/成功人话
4. **Brief 中间页/面板**：分组展示 + 可编辑要点（最小可先只读+重聊）；**认领并写成计划** → save_plan / 草稿，禁止 confirm_start
5. **Plan 落稿对齐**：认领后输出完整 ```plan 习惯章节；任务大纲默认 V1；V2/Later 折叠
6. **空心提醒（不拦）**：缺「怎样算做完 / 不做」时黄条；与 D0 文档关系写清
7. **门禁与预览验收**：主路径 30 秒走查；三入口各一条 happy path；认领后不可开跑；聊天仍不 spawn；回归既有写计划金样/契约测试

## 风险 / 待确认
- 澄清相与现有「多轮直接出 plan」如何并存：建议 **默认进澄清**；plan-only 与「你定」作逃逸
- Brief 是否落独立文件 vs 仅 session + plan 前缀：默认 **session 展示 + 认领写入 plan**，文件策略实现时二选一写死
- 与主观渴望 D0–D2 / guided G0–G4：本计划只做 **澄清相子集**；全量渴望/引导另轨，避免串味
- Prompt 过长拖慢首轮：澄清题模板短句，深度发现不进默认路径

## 结构对齐
- 配方 R-tool + 深度 D + app-shell；信息结构对齐「主路径 ≤5、同屏新概念 ≤3」
- 顺序：契约/路由 → prompt → 聊天 UI → Brief → plan 落稿 → 黄条 → 验收
