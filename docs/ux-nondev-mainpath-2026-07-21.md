## 0. 一句话结论

**最近打包交付的是「架构可维护 + 能力面齐全」的工程师控制台，不是 PRODUCT 写的「给非开发的轻量任务控制台」。**  
P2-16 主路径大改在工程上勾了 ✅（骨架、文案键、默认停拆分台），但 **成功标准 S-D（第一屏概念 ≤3）与故事板「小陈 10 分钟不碰终端」在真实 DOM 上仍失败**。用户打开最新包，看到的仍是：多页并存、按钮丛林、拆分/聊天/计划管理三套「计划」心智、日志与高级路由抢戏——所以「没看到很大改动」是正确感知，不是错觉。

## 1. 为什么「架构大改 / 主路径大改」用户几乎无感

### 1.1 两套「大改」各自改了什么

| 线 | 真源 | 实际改动重心 | 用户肉眼 |
|----|------|--------------|----------|
| **A0–A5 架构** | `architecture-redesign-2026-07-20.md` | 六边形、MVVM、gateway、facade 瘦身、IPC 单出口 | **几乎 0**：同一 HTML 壳 + strangler 双轨 |
| **P2-16 主路径** | `product-mainpath-optimize-2026-07-20.md` | 默认停拆分、三栏骨架、CTA 改名、阶段条、结果台区块、模板入口 | **中低**：能指认部分新词，但整体仍像旧壳叠功能 |
| **近一周 commit** | git log `web/` | 选框样式、role/scope 可写、sys-post PR、state 抽模块、打包路径修复 | **能力 + 可维护**，非「清爽一轮」 |

### 1.2 勾选 ✅ 与体感脱钩的机制

1. **完成定义偏工程**：S1「骨架」/ S9「骨架」/ X3「标记扫描」可绿；**没有**「非开发盲测走完故事板」门禁。  
2. **Strangler 保留全部旧 DOM**：`index.html` 仍挂大量 legacy id、hidden 钩子、双 phase（`AppViewModel` 的 `author|split|run|result` **与** `state.phase` 的 `pick|planning|confirm|running|done` **与** 7 个 `page-*`）。  
3. **能力默认可见面过大**：S-role、handoff Board、事件过滤 term/pretty/raw、计划管理换夹/其它位置、chooser「更多选项」——全在主壳可达，违反「高级默认折叠」。  
4. **CSS 是补丁层积**：约 **5900 行**（`plan.css` ~2000、`chat.css` ~1300、`monitor.css` ~1000），tokens 有了，**信息层级没重做**。  
5. **打包现在确实带得上 UI**（`c4f767e` embed 修复；`dist/CCO.app` 2026-07-21 15:51 含新 `index.html`）——**问题不是没打进包，而是包里的产品形态仍劝退主受众**。

### 1.3 与 PRODUCT 故事板的差距（小陈）

```text
PRODUCT 目标：
  开 cco → 选项目 → 聊天写计划 → 看全文改两句 → 分配 → 看波次 → 确认 → 看三块进度 → 巡检回补
  全程不碰终端、不写依赖表

当前真实路径（代码行为）：
  欢迎 → 加文件夹（路径心智）→ 选项目
    → H0 默认落地 **聊天**（即使磁盘上有上次 planned 拆分，也只 toast「顶栏返回确认」）
    → 聊完要 **保存为计划**（计划文件概念）再 **拆成步骤**
    → 常先撞 **执行选项弹层**（通道/并发/规划方式/自动开始）
    → 拆分台：三栏 + 顶栏 4 个次 CTA + 质量 details + 可选/系统分区 + 高级 role/scope
    → 执行台：KPI + 步骤卡 + 可展开的「日志控制台」（过滤/字号/导出/账本）
    → 结果台与 KPI 同卡混排；回补/接受遗漏/结束/回聊天并列
```

**心智三问** PRODUCT 要求 ≤3 概念；当前主路径同时出现：项目、会话、计划文件、计划管理、执行选项、波次、可选、系统收尾、通道、并发、巡检、回补……

## 3. 分屏深度审计（非开发视角）

### 3.1 欢迎页 — 尚可，但冷启动断点在「项目」

**已对齐**

- 定位句、五步缩写、添加项目、帮助入口清楚。  
- 模板按钮存在（出海落地页 / 通用大纲）。

**摩擦**

- 模板写「需先选中项目」：无项目时点了无闭环或要先懂「文件夹=项目」。  
- 「项目」对 PM 是业务名；UI 实际要的是 **本机目录**——缺少「这就是你的工作文件夹」人话与一次选夹即进入写计划。  
- 无「演示/演练一键」默认路径（fake）给首次零依赖体验（设置里才有演练通道）。

### 3.2 聊天（写计划）— 主窗，但像「IM + 文件管理 + 运维」

**已对齐**

- 保存后主 CTA「拆成步骤」命名正确（F2）。  
- 空态可挂模板；附图能力完整。

**摩擦**

| 问题 | 表现 | 对非开发 |
|------|------|----------|
| **双主按钮** | 「保存为计划」与「拆成步骤」 | 不懂为何 AI 说完还要再存一层文件 |
| **会话切换** | 会话 select + 新建/删 | 第三概念；首跑不需要 |
| **计划快览轨** | ☰ 展开列表 / 已执行过滤 | 与「计划管理」重复 |
| **环境条** | 环境检查横幅 | 必要但话术易恐吓 |
| **选项层** | 默认可能先出 chooser | 通道/并发/规划方式 = 劝退 |
| **头条文案** | 「先保存计划文档，再拆成步骤」 | 正确但像说明书，不像教练 |

**缺什么**

- 首条系统引导气泡：「用一句话说目标 → 我帮你写成计划 → 你点一下拆开」。  
- 「看起来对了就拆」一键（保存+拆 合并意图，底层仍可写文件）。  
- 生成后 **对照核对**（全文卡片在对话流内完成，而不是跳去计划管理）。

### 3.3 执行选项弹层（chooser）— 主路径不应默认出现

**问题**：点「拆成步骤」后若未开「跳过选项层」，用户必须理解：

- 规划方式：AI / 解析 / 模拟  
- 执行通道：默认 / 备用 / 演练  
- 运行方式：前台 / 后台 / 自动  
- 并发数  
- 拆分后自动开始  

对主受众：**这整层应不存在**（设置里高级默认；主路径 = 一点即拆，拆完停台）。

### 3.4 拆分台 — 结构对，密度与入口错

**已对齐（真有）**

- 三栏：波次时间线 · 卡片 · 详情。  
- 必做 / 可选 / 系统分区；可选勾选；「确认并开始」唯一开跑。  
- 人话依赖「等待：…」；规划日志默认折叠。  
- 默认 `autoStartAfterPlan` 停台（S0）。

**摩擦（劝退点）**

1. **入口**：H0 让「待确认」回聊天 → 核心屏被藏。  
2. **顶栏动作过多**：重新拆分 / 可并行 / 写回摘要 与主按钮同排；写回摘要属进阶，不该首屏。  
3. **质量区**：critic chips +「开启巡检并重拆」把系统能力推到确认前。  
4. **详情高级**：role / scope / provider 可写（S-role）——能力对，**默认 fold 不够「像不存在」**；编辑表单仍像配置台。  
5. **长按钮文案**：「重新拆分（保留你的修改）」占位大、扫读成本高。  
6. **无「这像不像你要的？」一句话确认**，只有工程向 meta。

### 3.5 执行台 — 进度有了，调试台没走远

**已对齐**

- KPI 五态中文；stall 人话条；步骤网格；日志默认折叠。

**摩擦**

- 展开日志后是 **完整 CLI 调试台**（过滤矩阵 + 原始/结构/终端 + 字号 + 导出 + handoff 账本）。  
- 主受众要的是：「点某步 → 看它在干什么（3–5 行人话）→ 卡住喊人」；不是 Board。  
- 「独立监视窗」对双屏开发者好，对 PM 噪音。

### 3.6 结果台 — 骨架对，收口感弱

**已对齐**

- 计划要点 / 已完成 / 遗漏；无巡检诚实文案入口；回补 / 接受遗漏。

**摩擦**

- 与执行 KPI **同卡片并存**，终态不像「一页报告」。  
- 动作：回补并再巡检 / 接受遗漏并结束 / 结束本轮 / 回聊天 —— 四个出口需决策树。  
- 无「给你老板看的三行摘要」主视觉。

### 3.7 计划管理 — 第二产品

换夹 / 打开夹 / 选文件 / 显示其它位置 / 双击编辑 —— 对「计划文档一等公民」工程师友好，**对主受众是第二个 App**。应降为「更多 → 管理计划文件」，主路径只保留聊天内卡片 + 弱列表。

### 3.8 设置 / 帮助 / 环境

- 设置四组方向对，但仍把「智能第二跳」「failover」「post-PR」与主路径用户同一平面。  
- 帮助标题「上手（模式 B）」+ R-S10…17 + TOML 路径 = **写给贡献者**，不是写给小陈。

## 4. 根因归纳（5 条）

1. **产品默认仍是「能力展览」**：能做的都露在壳上；「砍复杂度」只写在 PRODUCT，没变成删除/深藏的门禁。  
2. **核心屏（拆分）被 H0 聊天优先策略拆台**：工程为了「聊天是主窗」牺牲了「拆分必须被看见」。  
3. **「计划」有三套 UI**（聊天保存、计划管理页、chooser 选文件）→ 用户不知道真源在哪。  
4. **完成标准没有用户验收**：架构绿、测试绿、勾选绿 ≠ 非开发能独立跑通。  
5. **视觉一体未做减法**：V 组改了侧栏宽与按钮色，**没有**按概念预算删控件与合并页面。

## 5. 目标体验（改造后真源）

### 5.1 主路径只保留 4 个主表面

```text
① 首页/项目   选或添加「工作文件夹」
② 写计划      对话为主；模板；保存对用户可隐
③ 拆分台      唯一确认闸；默认进入且不可被聊天冲掉（待确认态）
④ 进度/结果   同一工作区两态：跑=进度；完=报告
```

其余全部进 **设置 / 更多 / 高级折叠**：计划文件管理、doctor 细节、日志调试台、provider/role/scope、sys-post、监视窗、会话多开。

### 5.2 入口路由修正（相对 H0）

| 条件 | 现在 | 目标 |
|------|------|------|
| 有活动 run | workspace 执行 | 同左 |
| planning | workspace | 同左 |
| **planned / confirmed 待确认** | **chat** + toast | **workspace 拆分台（强制可见）** |
| 无 job 无 run | chat | chat（或「写计划」全屏） |
| 终态未结束本轮 | 混在 workspace | 结果报告态为主 |

### 5.3 概念预算（硬）

| 屏 | 允许同时出现的新概念 | 禁止同屏 |
|----|----------------------|----------|
| 写计划 | 目标描述 · 模板 · 下一步「拆开」 | 通道、并发、会话管理、换夹 |
| 拆分台 | 波次 · 步骤 · 确认开始 | 写回摘要、巡检开关、role/scope（除非点高级） |
| 执行 | 步骤状态 · 卡住 · 停止 | 事件过滤矩阵、handoff、导出 |
| 结果 | 做完 · 遗漏 · 下一步（回补/结束） | KPI 调试墙、VERDICT |

### 5.4 文案语气（主路径）

| 用 | 不用 |
|----|------|
| 开始拆开计划 | start_plan_job / 模式 B |
| 看步骤并开始 | 确认并开始（可保留，但旁路词去掉「Mode B」） |
| 这一步在等… | depends_on / task_id |
| 好像卡住了 | stall / failover |
| 还没做完这些 | residual / VERDICT |

## 7. 用户验收清单（非开发脚本 · 门禁）

环境：最新 `package-app` 包；可用 fake/演练；无需读文档。

| # | 步骤 | 通过标准 |
|---|------|----------|
| 1 | 打开 App，不点帮助 | 10 秒内知道要先有「工作文件夹」 |
| 2 | 添加一个文件夹 | 无路径术语恐慌；立即进入写计划 |
| 3 | 用一句话或模板生成计划 | 不出现通道/并发表单 |
| 4 | 点主按钮进入拆分 | **自动停在拆分台**；能指出谁和谁一起 |
| 5 | 不勾选可选，点开始 | 明白可选不会跑 |
| 6 | 看执行 | 不打开日志也能知进度；卡住有人话 |
| 7 | 结束 | 一页看懂做完/遗漏；知道下一步点哪个 |
| 8 | 全程 | **不打开**计划管理、设置、独立监视窗也能完成 |

任一失败 = 本波未完成，不得只靠 `cargo test` / facade 行数宣称 UX ✅。
